---

扩展是一个文件夹：内含 `.spirit/extension.json`（Spirit 宣言转储）与一个纯 npm 的 `package.json`。Spirit 按用户、按宿主安装扩展，不放在工作区 `.spirit/` 下，并按来源市场对每次安装做隔离：安装身份为 `(源 id, name)`。

| 宿主    | 路径                                                    |
| ------- | ------------------------------------------------------- |
| Desktop | `{spiritDataDir}/extensions/desktop/<sourceId>/<name>/` |
| CLI     | `{spiritDataDir}/extensions/cli/<sourceId>/<name>/`     |

这与 [Skills](../customize/skills.mdx)（`SKILL.md` 文件夹）、[MCP](../customize/mcp.mdx)（外部 server）、[Hooks](../customize/hooks.mdx)（`hooks.json` 脚本）不同。`contributes.cli.hooks` 用来给 CLI TUI 槽位加样式，不是 `hooks.json`。扩展也可以在声明 `mcp`、`hooks`、`skills` 或 `rules` 后，用同样的文件规范捆绑这些资源。

每个已安装扩展都有启用开关。禁用或卸载后即停止贡献。打开开关即同意运行它声明的 MCP、agent hooks、skills 和 rules。

向导会询问扩展名（kebab-case）、显示名、一行描述以及要脚手架的能力。它会写入 `package.json`、`icon.svg` 与 `.spirit/extension.json`，并按你选择的能力追加对应文件（`skills/<name>/SKILL.md`、`rule.md`、`mcp.json`、`hooks.json`、`styles.css`、`index.mjs`），结束时打印一段可直接粘贴的市场条目。

脚本化使用时，每个提问都有对应 flag：`[target-dir]`、`--name`、`--display-name`、`--description`、`--capabilities <csv>`，以及跳过确认的 `--yes`。

```bash
npx @spiritagent/extension-toolkit check ./my-extension
```

<Tab value="手动创建">

扩展目录只需要两个文件——`.spirit/extension.json` 与 `package.json`——再加上它声明的能力文件：

```text
my-extension/
  .spirit/
    extension.json        # Spirit 宣言转储（必填）
  package.json            # 纯 npm；只读取 `main`
  icon.svg                # 可选；仅 SVG，禁止 <script>
  index.mjs               # 可选；`main` 引用的 activate 入口
  mcp.json                # 声明 mcp 时
  hooks.json              # 声明 hooks 时（agent hooks）
  rule.md                 # 声明 rules 时
  skills/<name>/SKILL.md  # 声明 skills 时
  styles.css              # 声明 desktop CSS 时（路径由宣言引用）
  cli-hooks.json          # 声明 CLI hooks 时（路径由宣言引用）
```

`package.json` 不携带任何 Spirit 字段——`name`、`version`、`description`、`author`、`homepage`、`license`、`main`、`keywords` 保持纯 npm 语义。宿主只读取 `main`，即 [`activate`](#activate) 的模块入口。

`.spirit/extension.json` 字段：

| 参数            | 说明                                                                                    |
| --------------- | --------------------------------------------------------------------------------------- |
| `schemaVersion` | 必填。必须为 `1`                                                                        |
| `name`          | 必填。kebab-case；在市场内即条目 id                                                     |
| `version`       | 必填。semver `major.minor.patch`；不支持 pre-release 后缀                               |
| `sourceId`      | 必填。所属市场的源 id。ZIP 包可自声明任意值（例如 `"self-declared"`）；安装管线会重写它 |
| `displayName`   | 必填。用户可见名称                                                                      |
| `description`   | 必填。一行概述                                                                          |
| `icon`          | 可选。相对扩展根的 SVG 路径                                                             |
| `author`        | 可选。`{ name, email?, url? }` 或 npm 风格字符串 `"Name <email> (url)"`                 |
| `category`      | 可选。单个字符串                                                                        |
| `keywords`      | 可选。搜索关键字字符串数组                                                              |
| `homepage`      | 可选。项目 URL                                                                          |
| `manifest`      | 必填。运行时宣言——见下方「`manifest` 宣言」一节                                         |

转储不携带 `source` 与策展字段（`reviewStatus`、`featured`）——它们属于市场条目。

声明的文件必须存在且合法：声明了 `mcp`、`hooks`、`skills` 或 `rules` 却缺少对应文件，校验与安装都会失败。包内存在但未声明的文件会被忽略，永不加载。

</Tab>
</Tabs>

## `manifest` 宣言

`manifest` 对象是扩展的运行时宣言：支持哪些宿主、何时激活、贡献什么。在市场条目中，宣言由市场运营者背书；在 ZIP 包中，宣言是自声明的，并由审核确认门槛把关。

### 能力

| 值                   | 运行时                                                                |
| -------------------- | --------------------------------------------------------------------- |
| `tool-definitions`   | 须与 `tool-execution` 同时声明，才会把 `contributes.tools` 暴露给模型 |
| `tool-execution`     | 须与 `tool-definitions` 同时声明，才会执行这些工具                    |
| `system-prompt`      | 须与 `main` 同时具备，才会贡献 system 片段                            |
| `desktop-ui`         | 必须与 `contributes.desktop` 成对出现                                 |
| `cli-ui`             | 必须与 `contributes.cli` 成对出现                                     |
| `mcp`                | 必须与 `contributes.mcp` 成对出现；加载包根 `mcp.json`                |
| `hooks`              | 必须与 `contributes.hooks` 成对出现；加载包根 `hooks.json`            |
| `skills`             | 必须与 `contributes.skills` 成对出现；加载 `skills/<name>/SKILL.md`   |
| `rules`              | 必须与 `contributes.rules` 成对出现；加载包根 `rule.md`               |
| `approval-flow`      | 仅声明。审批由各工具的 `approvalMode` 驱动                            |
| `questions-flow`     | 仅声明。问卷由 `approvalMode: need-questions` 驱动                    |
| `settings`           | 仅声明。设置来自 `settingsSchema`                                     |
| `secret-storage`     | 与 `secretSlots` 一起使用                                             |
| `structured-results` | 仅声明                                                                |

`desktop-ui` / `cli-ui` / `mcp` / `hooks` / `skills` / `rules` 与对应的 `contributes` 项必须同时有或同时没有。

### 激活事件

| 事件                   | 何时触发       |
| ---------------------- | -------------- |
| `onStartup`            | 宿主预热       |
| `onExtensionInstalled` | 安装完成之后   |
| `onSessionOpened`      | 会话变为活动   |
| `onSessionReset`       | 会话重置       |
| `onUserMessage`        | 用户提交消息   |
| `onToolCall`           | 工具即将运行   |
| `onToolResult`         | 工具结果可用   |
| `onApprovalResolved`   | 审批决定已解析 |

扩展列出该事件且有可读的 `main` 时，宿主会调用 `activate`。

### `contributes.tools`

| 参数            | 说明                                                 |
| --------------- | ---------------------------------------------------- |
| `name`          | 必填。`[a-z0-9]+(?:[._-][a-z0-9]+)*`                 |
| `description`   | 必填。展示给模型                                     |
| `inputSchema`   | 必填。JSON Schema 对象                               |
| `outputSchema`  | 可选。JSON Schema 对象                               |
| `approvalMode`  | 可选。`allowed`、`need-approval` 或 `need-questions` |
| `executionMode` | 可选。`foreground` 或 `background`                   |

模型看到的不是原始 `name`。宿主会生成形如 `extension__{id}__{tool}__{hash}` 的调用名。

### `contributes.desktop`

需要 `desktop-ui`。

| 参数           | 说明                                                          |
| -------------- | ------------------------------------------------------------- |
| `css[].path`   | 必填。相对包根的 CSS 文件                                     |
| `css[].media`  | 可选。CSS media query                                         |
| `settingsPage` | 可选。`true`、`{}` 或 `{ title }` — 在 Desktop 设置中增加入口 |
| `views[].id`   | 必填。kebab-case，同一扩展内唯一                                     |
| `views[].path` | 必填。相对包根的预编译单文件 ESM（`.js` / `.mjs`）。宿主不编译 TSX。相对 import 会 404——protocol 只提供这一份文件 |
| `views[].title` | 可选。Dialog 标题                                                   |
| `views[].width` | 可选。Dialog 宽度                                                   |
| `views[].height` | 可选。Dialog 高度                                                  |
| `views[].chrome` | 可选。Dialog 外壳：`default`（标题 + 关闭）、`close-only`（隐藏标题、保留关闭）或 `none`（两者都隐藏）。省略等同 `default`。 |

默认导出：`export default function View({ params, close })`。`close(result)` 结束 View。宿主注入 React 与 `@spirit/desktop-ui`。

### `contributes.cli`

需要 `cli-ui`。`hooks` 是带 `path` 的对象，不是内联数组：

```json
{
  "hooks": { "path": "cli-hooks.json" }
}
```

该文件必须是 `{ "hooks": [ ... ] }`。

| 参数      | 说明                                                                 |
| --------- | -------------------------------------------------------------------- |
| `slot`    | 必填。下列槽位之一                                                   |
| `variant` | 可选。`default`、`accented`、`muted`、`warning`、`success`、`danger` |
| `tokens`  | 可选。`{ foreground?, border?, accent? }`                            |
| `prefix`  | 可选。字符串                                                         |
| `suffix`  | 可选。字符串                                                         |

槽位：`message.user`、`message.assistant`、`message.tool`、`assistant.thinking`、`input.frame`、`bottom_form`、`bottom_form.section`、`slash_suggestions`、`approval.panel`、`questions.panel`。

Token 角色：`default`、`primary`、`secondary`、`muted`、`accent`、`success`、`warning`、`danger`。

```json
{
  "hooks": [
    {
      "slot": "input.frame",
      "variant": "accented",
      "tokens": { "border": "accent" },
      "prefix": "[",
      "suffix": "]"
    }
  ]
}
```

### 捆绑的 MCP、Hooks、Skills 与 Rules

须与对应能力成对。`contributes.mcp`、`contributes.hooks`、`contributes.skills`、`contributes.rules` 取 `true` 或 `{}`。路径是约定路径，不允许自定义 path。

| 贡献面      | 能力     | 文件                                                                        |
| ----------- | -------- | --------------------------------------------------------------------------- |
| MCP         | `mcp`    | 包根 `mcp.json`（与用户/工作区 MCP 同 schema）                              |
| Agent hooks | `hooks`  | 包根 `hooks.json`（与 agent hooks 同 schema；不是 `contributes.cli.hooks`） |
| Skills      | `skills` | `skills/<name>/SKILL.md`                                                    |
| Rules       | `rules`  | 包根 `rule.md`                                                              |

已声明但文件缺失或非法则安装失败。包内有文件但未声明则忽略，永不加载。

这些文件里的相对 `command` 与 `cwd` 相对扩展根解析。MCP stdio 省略 `cwd` 时默认扩展根。PATH 上的裸命令不变。

扩展启用后，这些贡献会 overlay 进会话运行时，**不会**出现在 **设置 → MCPs | Hooks | Skills | Rules**。同名冲突：工作区优先于用户，用户优先于扩展。

在 `tools/call` 期间，捆绑 MCP 可以在客户端声明了 `experimental["spirit/ui"]` 时发出 JSON-RPC 请求 `spirit/ui/open`（`{ viewId, params }`）。Spirit 只打开同一扩展在 `contributes.desktop.views` 里声明的 View；用户/工作区 MCP 一律拒绝。Dialog 会挡住这次 `tools/call`，`close(result)` 的结果回到同一条请求。无窗口宿主返回 `{ "kind": "unavailable", "reason": "host-has-no-ui" }`，工具应自行降级。

### `settingsSchema`

| 参数           | 说明                                                   |
| -------------- | ------------------------------------------------------ |
| `key`          | 必填。与工具名相同的模式                               |
| `type`         | 必填。`string`、`boolean`、`number` 或 `select`        |
| `title`        | 必填。UI 标签                                          |
| `description`  | 可选                                                   |
| `placeholder`  | 可选                                                   |
| `required`     | 可选。布尔值                                           |
| `defaultValue` | 可选。须与 `type` 匹配                                 |
| `options`      | `select` 时必填。`{ value, label, description? }` 数组 |

值为 `string`、`number`、`boolean` 或 `null`。`null` 会清空非必填项。

### `secretSlots`

| 参数          | 说明         |
| ------------- | ------------ |
| `key`         | 必填         |
| `title`       | 必填         |
| `description` | 可选         |
| `required`    | 可选。布尔值 |

Desktop 把密钥存在操作系统钥匙串。在 CLI daemon 路径上，`secrets.set` / `secrets.delete` 可能不可用。

## `activate`

`main` 通过动态 `import` 加载。导出以下之一：

- `export function activate(ctx) { ... }`
- `export default function activate(ctx) { ... }`
- `export default { activate }`

### `ctx`

| 参数              | 说明                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `extension`       | `{ id, name, version, directoryPath, manifestPath, main }`                               |
| `host`            | 宿主 API。Desktop 实现 `showMessageBox` 与 `ui.open` / `ui.close`。CLI 为 `{}`           |
| `log`             | `(message: string) => void`                                                              |
| `settings`        | `get(key)`、`getAll()`、`set(key, value)`、`setAll(values)`                              |
| `secrets`         | `get(key)`、`has(key)`、`set(key, value)`、`delete(key)` — 键必须在 `secretSlots` 中声明 |
| `activationEvent` | 可选。`{ type, detail? }`                                                                |

### 返回值

返回一个对象，或从模块导出相同字段。

| 参数              | 说明                                                           |
| ----------------- | -------------------------------------------------------------- |
| `tools`           | `Record<string, (ctx) => unknown>`。键是宣言里的工具名         |
| `invokeTool`      | `(ctx) => unknown`。存在时优先于 `tools[name]`                 |
| `systemPrompt`    | 静态 system 片段                                               |
| `getSystemPrompt` | `() => string \| Promise<string>`。存在时优先于 `systemPrompt` |
| `onEvent`         | `(event) => void`                                              |
| `dispose`         | `() => void`。卸载或重载时调用                                 |

### 工具处理函数的 `ctx`

| 参数              | 说明                                                  |
| ----------------- | ----------------------------------------------------- |
| `extension`       | 与 `activate` 相同的运行时信息                        |
| `host`            | 同一宿主 API                                          |
| `toolName`        | 宣言中的工具名                                        |
| `arguments`       | 模型传入的对象                                        |
| `log`             | 同一日志函数                                          |
| `settings`        | 同一设置访问器                                        |
| `secrets`         | 同一密钥访问器                                        |
| `toolCallId`      | 可选                                                  |
| `questionsResult` | 可选。`approvalMode` 为 `need-questions` 时由宿主注入 |

`string` 结果原样返回。其他值会 `JSON.stringify(value, null, 2)`。`undefined` 变成 `""`。

### Desktop `host.showMessageBox`

| 参数        | 说明                                                 |
| ----------- | ---------------------------------------------------- |
| `title`     | 必填。字符串                                         |
| `message`   | 必填。字符串                                         |
| `detail`    | 可选。字符串                                         |
| `buttons`   | 可选。字符串数组                                     |
| `cancelId`  | 可选。数字                                           |
| `defaultId` | 可选。数字                                           |
| `noLink`    | 可选。布尔值                                         |
| `type`      | 可选。`none`、`info`、`error`、`question`、`warning` |

```js
export function activate(ctx) {
  return {
    systemPrompt: "Use lookup_item when the user asks for an item by id.",
    async invokeTool({ toolName, arguments: args, settings, secrets }) {
      if (toolName !== "lookup_item") {
        throw new Error(`Unknown tool: ${toolName}`);
      }
      const region = await settings.get("region");
      const token = await secrets.get("api_token");
      return { id: args.id, region, hasToken: Boolean(token) };
    },
    dispose() {
      ctx.log("example-extension disposed");
    },
  };
}
```

## 打包为 ZIP 分发

把扩展目录打包为可分享的 ZIP（内容加 `.spirit/extension.json`）：

```bash
npx @spiritagent/extension-toolkit pack ./my-extension
```

命令会先校验包，再把 `<name>-<version>.zip` 写入当前目录。用户在**扩展**页导入该 ZIP，或用 `spirit extension import`；它会进入他们的个人市场。见[扩展](../customize/extensions.mdx)。

如需把扩展上架到市场，见[用 publish 发布](#用-publish-发布)。

## 搭建远程扩展市场

远程扩展市场就是一个提供 `.spirit/marketplace.json` 索引的可服务目录：Git 仓库、静态站点或本地目录。用户通过 `spirit extension marketplace add <url|path>` 或 Desktop **扩展**页添加它，然后浏览并安装其中的条目。

<Tabs items={["使用模板仓库", "手动创建"]}>
<Tab value="使用模板仓库">

[Use this template](https://github.com/new?template_owner=SpiritAgents&template_name=extension-template) 可以从 `SpiritAgents/extension-template` 一键创建你自己的市场仓库。

模板自带注册处布局、两个示例扩展，以及在每次 push 与 PR 上校验注册处的 CI。发布一个扩展：

1. 用 `npm create @spiritagent/extension` 脚手架。
2. 运行 `npx @spiritagent/extension-toolkit publish ./my-extension /path/to/your-marketplace-clone`——它会把扩展复制进 `extensions/`，并把条目合并进 `.spirit/marketplace.json`。见[用 publish 发布](#用-publish-发布)。
3. 推送——用户用它的 Git URL 添加市场。

</Tab>
<Tab value="手动创建">

市场根目录 = 索引 + 每个扩展一个内容目录：

```text
my-marketplace/
  .spirit/
    marketplace.json  # 索引
  extensions/
    my-extension/     # 内容目录（纯 npm 包 + 能力文件）
      icon.svg
      package.json
      ...
```

`marketplace.json` 内的相对路径相对市场根目录解析，禁止 `..` 段与绝对路径。

条目字段按语义分组：

- **身份**——`name`（kebab-case，条目 id）、`version`（semver，不含 pre-release）、`source`：本地内容为根相对路径字符串（如 `"./extensions/my-extension"`），或 `{ "source": "npm", "package": "@scope/name@1.0.0" }` 钉住精确 npm 版本（安装时会按 packument 的 SRI 哈希校验完整性）。
- **展示**——`displayName`、`description`、`icon`（根相对 SVG 路径）、`category`、`keywords`、`homepage`、`author`。
- **宣言**——`manifest`：即「`manifest` 宣言」一节描述的运行时宣言。市场为它背书；包不能自证能力。
- **策展**——`featured` 与 `reviewStatus`（`unverified` / `verified` / `revoked`）。

也可以用 `extension-toolkit publish` 自动合并条目——见[用 publish 发布](#用-publish-发布)。

本地校验注册处——纯离线：schema、kebab-case 名称、不含 pre-release 的 semver、npm source 格式、本地 source 的声明-内容文件、图标规则：

```bash
npx -y @spiritagent/extension-toolkit marketplace check .
```

审核纪律：新增条目或变动 `version` 的 PR 必须保持 `reviewStatus: "unverified"`；人工复核后在单独提交中晋升为 `verified`。模板仓库的 `.github/workflows/marketplace.yml` 即参考实现——它相对 PR 基线 diff 索引。

</Tab>
</Tabs>

### 本地市场

任何带 `.spirit/marketplace.json` 的本地目录都可以作为市场添加——用 `spirit extension marketplace add <path>` 或 Desktop 的**从磁盘添加**。本地市场原地读取、无需 CI，因此也是扩展作者的开发循环：编辑、重装、重复。

### 用 publish 发布

`extension-toolkit publish` 把扩展的 `.spirit/extension.json` 合并进目标市场的 `.spirit/marketplace.json`，并按条目 source 的需要复制内容：

```bash
npx @spiritagent/extension-toolkit publish ./my-extension ./my-marketplace
```

- 第一个参数是扩展目录，第二个是市场根目录——任何带 `.spirit/marketplace.json` 的本地目录：模板仓库克隆、`{spiritDataDir}/marketplaces/personal` 的个人市场等。
- `--source local`（默认）：把完整的包复制进市场的 `extensions/<name>/`——含 `.spirit/extension.json`，排除 `node_modules` 与 `.git`——并把条目 `source` 指向该目录。
- `--source npm`：从扩展的 `package.json` 读 `name@version` 钉版作为条目的 npm `source`；只把宣言声明的图标复制进 `extensions/<name>/`（图标由市场自托管）。npm 包本身的发布仍由你用 npm CLI 完成。
- `--dry-run`：打印将写入的条目与计划动作，不落盘。
- 合并规则：同名条目原位替换，否则追加；新条目或 `version` 变动时 `reviewStatus` 回落为 `unverified`，同版本重发保留；`featured` 等策展字段始终保留市场侧原值。
- 发布前会跑与 `check` 相同的校验；失败则不写任何文件。
