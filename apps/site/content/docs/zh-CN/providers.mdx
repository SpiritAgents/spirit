{{product.name|mdx}} 是 BYOK。你在提供商控制台创建 Key，粘进 Desktop 或 CLI，{{product.name|mdx}} 写入操作系统钥匙串。更换提供商不会改变你打开工作区、审批编辑或运行 Agent 的方式。

连接向导在 Desktop 是 **设置 → 模型**，在 CLI 是 `/model add` 或 `spirit model add`。附加字段只在该提供商需要时出现。

{{product.name|mdx}} 用下面四种传输之一和提供商通信。向导会固定类型，或让你选。

| 传输                | 向导标签                           | 典型用途                                                           |
| ------------------- | ---------------------------------- | ------------------------------------------------------------------ |
| `openai-compatible` | Chat Completions API               | 大多数 OpenAI 兼容端点                                             |
| `open-responses`    | Responses API / Open Responses API | OpenAI、Azure、Vercel AI Gateway、Hugging Face，以及可选的网关路径 |
| `anthropic`         | Messages API                       | Anthropic、MiniMax，以及可选的 Messages 兼容端点                   |
| `bedrock`           | Amazon Bedrock                     | 仅 Amazon Bedrock                                                  |

Google 与 Vertex AI 预设固定走 Chat Completions——向导不提供传输选择器。

有的提供商在 Key 之外还有第二维：

- **区域站点** — Moonshot AI、硅基流动、MiniMax（中国 / 国际）；阿里巴巴（区域 + `workspaceId`）；腾讯 TokenHub（广州 / 新加坡）
- **套餐端点** — 阿里巴巴 Token Plan、阶跃星辰 Step Plan、Z.ai / 智谱 AI GLM Coding Plan
- **云厂商字段** — Bedrock 区域、Azure 资源名、Cloudflare 账户（及可选 gateway）、Vertex 项目 / 位置

没有这些维的提供商，向导就是：Key → 导入模型 → 选当前语言模型。

{{product.name|mdx}} 会导入模型目录，并让你指定当前语言模型；目录标了生图 / 生视频 / 次要语言模型时再指定对应槽位。推理选项跟随各模型声明的 `supportedReasoningEfforts`。联网搜索等提供商暴露的工具按提供商声明，由**提供商工具**开关统一控制——见[工具](./agent/tools.mdx#provider-tools)。

向导写入 `config.json` 的是完全声明式的条目：最终 API Base、传输、SDK 适配器，以及提供商工具 / 文件上传 / 生成 API 声明。运行时原样读取这些声明，不会按提供商身份重新推导——你的修改会保留，只有重连会重置向导拥有的键（见[配置](./config.mdx)）。

## 目录

以下是连接选择器里的提供商，顺序一致。每家写 Key、传输、附加字段，以及向导在 Key 之外声明的内容。除非特别说明，凭证形态都是单个 API Key，存入钥匙串。上面的 Desktop / CLI 向导对每家都一样。

### OpenAI

在 [OpenAI 平台](https://platform.openai.com/api-keys) 创建 API Key。{{product.name|mdx}} 不出售 OpenAI 额度。

向导固定 **Responses API**（`open-responses`），没有传输选择器。默认 Base：`https://api.openai.com/v1`。

导入后即可对话。推理跟模型走。生图 / 生视频只在目录标了对应能力时出现，到生图 / 生视频槽位里指定。

声明：**联网搜索**提供商工具（由上游在请求内执行）和生图 API。

### Anthropic

在 [Anthropic 控制台](https://console.anthropic.com/settings/keys) 创建 API Key。

固定 **Messages API**（`anthropic`）。默认 Base：`https://api.anthropic.com/v1`。

导入后即可对话。推理跟模型走。除非目录后来标了生图 / 生视频，否则没有对应槽位。

### Vercel AI Gateway

在 [Vercel AI Gateway](https://vercel.com/docs/ai-gateway) 控制台创建 Key。

### Amazon Bedrock

在 [AWS Bedrock 控制台](https://console.aws.amazon.com/bedrock) 创建 Bearer API Key，或能调用 Bedrock 的 IAM 用户。

固定 **Amazon Bedrock**（`bedrock`）。默认主机形态：`https://bedrock.us-east-1.amazonaws.com`。

- **AWS 区域**（必填），例如 `us-east-1`
- **认证**：**Bearer** 或 **IAM**
  - Bearer — 粘贴 Bedrock API Key 和模型 id。**不会**自动拉模型列表。
  - IAM — Access Key ID + Secret Access Key。{{product.name|mdx}} 从账户列出 foundation models。

选定模型后即可对话。其他能力跟该模型走。Bearer 只能做推理。`ListFoundationModels` 不接受 Bearer，所以导入目录需要 IAM。

区域会物化进最终 API Base 和 `options.awsRegion`。Bearer 存为提供商 Key；IAM 存为 `accessKeyId` / `secretAccessKey` 凭证槽位。

### Google Vertex AI

使用已开通 Vertex AI 的 GCP 项目。认证是 ADC、服务账号或 Express API Key，不是普通 OpenAI Key。

固定 **Chat Completions API**，向导不提供传输选择器。Base 为 `https://{location}-aiplatform.googleapis.com/v1/projects/{project}/locations/{location}`。

- **GCP 项目 ID** 和 **位置**（必填），例如 `us-central1`
- **认证**
  - **ADC** — 本机 Application Default Credentials（`GOOGLE_APPLICATION_CREDENTIALS`）
  - **服务账号** — client email + 私钥；用来拉模型列表
  - **Express API Key** — 不能自动拉目录，需手填模型 id

选定模型后即可对话。没有 GCP 项目、只用 AI Studio Key 时，走 [Google](#google)。Express 模式不能导入模型列表。服务账号模式要同时有 email 和私钥才能列模型。

服务账号存为 `clientEmail` / `privateKey` 凭证槽位，并带 `options.project` / `options.location`；Express 模式写入 Express API Base，不需要项目 / 位置。

### 自定义

使用该端点要求的 API Key。{{product.name|mdx}} 不托管自定义提供商。

选择器：**Chat Completions**、**Open Responses** 或 **Messages**。必须填写 **Base URL**。留空时占位默认是 `https://api.openai.com/v1`。

填写厂商文档里的根地址，若对方要求版本后缀（`/v1`、`/v1/openai` 等）一并带上。自定义端点 {{product.name|mdx}} 不会猜路径。

还可以给提供商条目起显示名，方便区分多条自定义端点。

连接后导入或手填模型 id。若端点没有 {{product.name|mdx}} 能读的目录，在向导里自行标记对话 / 生图 / 生视频能力。
