Shared user data follows the build quality, not the operating system's application-data directory.

## Data directory

Override with `SPIRIT_DATA_DIR`. The server can also use `SPIRIT_SERVER_DATA_DIR` (wins over the former).

| Build | macOS / Linux | Windows |
| --- | --- | --- |
| Stable | `~/{{product.stable.userDataFolderName}}` | `%USERPROFILE%\{{product.stable.userDataFolderName}}` |
| Dev | `~/{{product.dev.userDataFolderName}}` | `%USERPROFILE%\{{product.dev.userDataFolderName}}` |

Breaking change: old platform data directories are not read or migrated automatically. Explicit data-directory overrides remain supported. Electron caches, browser storage, and window state remain in the private platform application directory.

Typical files:

```
{spiritDataDir}/
  config.json
  mcp.json
  hooks.json
  rule.md
  skills/
  chats/
  plans/
  extensions/
  automations/
  dreams/
  server.token
  server/instances/
```

CLI binaries use SPIRIT_HOME. On Unix, the Stable install and shared data may have the same parent directory; bin/ and cli/ remain installation files. The installer setting does not select the shared-data directory.

## config.json v2

`schemaVersion` must be `2`. Version 1 is rejected — delete the old file and [reconnect a provider](./providers.mdx).

Core fields:

- `providerGroups` — connected houses, API base, transport, models
- `activeModel`
- `imageGenerationModel` / `videoGenerationModel` / `secondaryLanguageModel`
- `permission` — permission allowlist rules

Keys are **not** in this file. They live in the [keyring](./security.mdx).

### permission

`permission` pins down what individual shell commands and file paths may do, on top of the session [approval level](./agent/approvals.mdx). Keys are tool names (`shell`, `read_file`); values map wildcard patterns to `allow`, `ask`, or `deny`.

```json
{
  "permission": {
    "shell": {
      "git *": "allow",
      "rm -rf *": "deny"
    }
  }
}
```

`deny` is absolute — no approval level, hook, or session memory overrides it. Pattern syntax, path semantics, and the full action list are in [Approvals](./agent/approvals.mdx). Verify rules without running anything: `spirit permission check --shell "git status"`.

The old `tool-permissions.json` (written by the "Always Trust" button) is deprecated: the code no longer reads or writes it, and there is no automatic migration. Leftover files are inert — delete them manually.

## Workspace `{{product.workspaceDataFolderName}}/`

| Path                 | Role                                       |
| -------------------- | ------------------------------------------ |
| `{{product.workspaceDataFolderName}}/rule.md`    | Workspace [rule](./customize/rules.mdx)    |
| `{{product.workspaceDataFolderName}}/skills/`    | Workspace [skills](./customize/skills.mdx) |
| `{{product.workspaceDataFolderName}}/mcp.json`   | Workspace [MCP](./customize/mcp.mdx)       |
| `{{product.workspaceDataFolderName}}/hooks.json` | Workspace [hooks](./customize/hooks.mdx)   |

Also used: `{workspace}/AGENTS.md`, `{workspace}/.agents/skills/`, `{workspace}/plans/`.

## Environment variables

| Variable                                                          | Role                               |
| ----------------------------------------------------------------- | ---------------------------------- |
| `SPIRIT_DATA_DIR`                                                 | Data directory                     |
| `SPIRIT_SERVER_DATA_DIR`                                          | Server data directory (wins)       |
| `SPIRIT_ACP_DATA_DIR` / `SPIRIT_ACP_WORKSPACE`                    | [ACP](./acp.mdx)                   |
| `SPIRIT_HOME` / `SPIRIT_VERSION` / `SPIRIT_DOWNLOAD_HOST`         | CLI installer                      |
| `SPIRIT_API_KEY` / `SPIRIT_API_BASE`                              | [CLI](./cli.mdx) process overrides |
| `SPIRIT_WEB_HOST` / `SPIRIT_WEB_PORT` / `SPIRIT_DESKTOP_WEB_HOST` | Desktop Web Host                   |
| `SPIRIT_TERMINAL_SHELL`                                           | Desktop PTY shell                  |
