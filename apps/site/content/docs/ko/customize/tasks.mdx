작업은 {{product.name|mdx}} Desktop 명령 팔레트에서 미리 정의된 작업공간 명령을 실행합니다. 팔레트를 열고(`Mod+Shift+P`) **작업공간 → 작업 실행**을 선택한 다음 두 번째 수준 목록에서 작업을 선택하세요. 작업은 오른쪽 도구 패널의 터미널 탭에서 실행됩니다. **작업공간** 그룹은 유효한 작업이 하나 이상 있을 때만 팔레트에 표시됩니다.

{{product.name|mdx}} 작업은 VS Code Tasks가 아닌 자체 시스템입니다. 엄격한 JSON {{product.name|mdx}} 형식을 읽고, 호환성 가져오기로 VS Code의 `tasks.json`을 읽습니다 — 명확하게 정의된 VS Code 필드의 하위 집합만 지원합니다. 구성한 그대로 실행할 수 없는 작업은 절반만 구성된 상태로 실행되는 대신 완전히 숨겨집니다. [작업이 숨겨지는 이유](#작업이-숨겨지는-이유)를 참조하세요.

## 작업 파일

세 가지 소스를 읽으며, 우선순위가 높은 순서는 다음과 같습니다:

| 우선순위 | 소스                             | 필수 마커            | 참고                               |
| -------- | -------------------------------- | -------------------- | ---------------------------------- |
| 1        | `<workspace>/{{product.workspaceDataFolderName}}/tasks.json` | `"schemaVersion": 1` | {{product.name|mdx}} 자체 형식                   |
| 2        | `<data dir>/tasks.json`          | `"schemaVersion": 1` | 사용자 수준, 모든 작업공간에 적용  |
| 3        | `<workspace>/.vscode/tasks.json` | `"version": "2.0.0"` | VS Code 호환성 가져오기, 읽기 전용 |

작업공간 루트만 스캔하며 중첩 디렉터리는 스캔하지 않습니다. `<data dir>`는 {{product.name|mdx}} 데이터 디렉터리입니다(예: macOS에서는 `~/{{product.stable.userDataFolderName}}`). 파일이 없거나, 읽을 수 없거나, 잘못된 JSON이거나, 마커가 올바르지 않으면 해당 파일은 작업을 제공하지 않습니다.

세 파일은 실시간으로 감시되며, 하나라도 변경되면 팔레트 목록이 자동으로 새로 고쳐집니다.

세 소스는 하나의 네임스페이스로 병합됩니다. 여러 소스가 동일한 `label`을 정의하면 팔레트 목록과 `dependsOn` 참조 모두에서 우선순위가 가장 높은 소스가 우선합니다.

`.vscode/tasks.json`은 실제 환경의 파일이 JSONC이므로 관대하게 파싱됩니다. `//` 및 `/* */` 주석과 후행 쉼표를 허용합니다. {{product.name|mdx}} 자체 파일은 엄격한 JSON이며, 주석이 있으면 파일이 무효가 됩니다.

## 워크스페이스 신뢰

워크스페이스 작업 파일은 저장소와 함께 도착하므로 신뢰할 수 없는 데이터입니다: `{{product.workspaceDataFolderName}}/tasks.json`과 `.vscode/tasks.json`은 워크스페이스 내용을 승인한 후에만 로드됩니다. 사용자 수준 `tasks.json`({{product.name|mdx}} 데이터 디렉터리)은 암묵적으로 신뢰되며 항상 로드됩니다.

{{product.name|mdx}} Desktop이 워크스페이스 작업 파일(또는 그 변경)을 감지하면 한 번 묻습니다: 프롬프트에는 사용 가능해질 작업과 해당 명령이 나열되고, 항목을 클릭하면 소스 파일이 열립니다. 워크스페이스 훅도 승인이 필요하면 두 목록이 하나의 결합된 대화 상자에 표시됩니다.

- **한 번 허용** — 작업은 이 세션에서만 로드됩니다.
- **항상 신뢰** — 정확히 이 파일 내용에 대해 기억됩니다.
- **거부** — 워크스페이스 작업은 사용할 수 없게 유지됩니다. 거부는 이 세션에서 해당 내용에 대해 기억됩니다.

파일을 편집하면 다시 묻습니다(승인은 콘텐츠 해시에 연결됨). 거부에서 복구하려면 파일을 편집하거나(다시 묻습니다) 앱을 다시 시작하세요.

이 게이트는 자동 실행 트리거의 구조적 전제 조건입니다: `runOn: "folderOpen"`은 승인 후에만 실행되고 `worktreeCreated`는 계속 비활성화됩니다.

## 필드

필드별 동작은 병합 후 평가됩니다: 파일 수준 기본값 < 파일 수준 OS 블록 < 작업 < 작업 수준 OS 블록.

### 핵심 필드

| 필드                                   | 동작   | 설명                                                                                                                                                                                                                    |
| -------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`                                | 필수   | 비어 있지 않은 label이 없는 항목은 완전히 제외됩니다 — 메뉴와 종속성 그래프에 도달하지 않습니다                                                                                                                         |
| `type`                                 | 지원됨 | `shell`(기본값) 또는 `process`. 다른 문자열(`npm`, `grunt`, …)은 확장이 커스터마이즈한 항목이며 완전히 무시됩니다: 숨겨지지도 않고 목록에도 나타나지 않으며, 형제 항목에도 영향을 주지 않습니다                         |
| `command`                              | 지원됨 | `string`, `string[]` 또는 `{ value, quoting }`. 병합된 command가 없는 작업은 숨겨집니다 — `shell` 작업도 마찬가지입니다(VS Code보다 엄격)                                                                               |
| `args`                                 | 지원됨 | `string` 또는 `{ value, quoting }`의 배열                                                                                                                                                                               |
| `quoting`                              | 지원됨 | `escape`, `strong`(기본값) 또는 `weak`. 잘못된 값은 `strong`으로 되돌아갑니다. `args`와 객체 형태 `{ value, quoting }`에 적용됩니다. 문자열 형태의 `command`는 셸에 그대로 전달되므로 원시 셸 구문을 포함할 수 있습니다 |
| `options.cwd`                          | 지원됨 | 프로세스의 작업 디렉터리                                                                                                                                                                                                |
| `options.env`                          | 지원됨 | 호스트 환경 위에 병합되는 추가 환경 변수                                                                                                                                                                                |

| `windows` / `osx` / `linux`(작업 수준) | 지원됨 | 현재 OS에 대한 `{ command, args, options }` 재정의.                                                                                                                                                                     |

| `promptOnClose`                        | 지원됨 | 프로세스가 살아 있는 동안 탭을 닫으면 확인을 요청합니다                                                                                                                                                                 |

| `detail`                               | 지원됨 | 팔레트 목록에서 label 옆에 표시됩니다                                                                                                                                                                                   |
| `icon.id`                              | 지원됨 | 메뉴 아이콘: {{product.name|mdx}} Icons 우선, 그 다음 Lucide, 기본값으로 터미널 글리프 사용                                                                                                                                           |

### 무시되는 필드

다음 필드가 있어도 작업은 숨겨지지 않습니다: `problemMatcher`(모든 형태, 모든 수준), `presentation.revealProblems`, `group`(빌드/테스트 그룹화), `icon.color`, `presentation.showReuseMessage`, `presentation.group`, `inAgents`. 파일 수준 `inputs` 배열은 아예 읽지 않습니다 — 단, 작업 안의 `${input:*}` *참조*는 해당 작업을 숨깁니다([변수](#변수) 참조).

## 변수

작업이 해석될 때 치환되는 지원 참조:

| 변수                         | 값                                               |
| ---------------------------- | ------------------------------------------------ |
| `${workspaceFolder}`         | 작업공간 루트 경로                               |
| `${workspaceFolderBasename}` | 작업공간 루트 디렉터리 이름                      |
| `${cwd}`                     | {{product.name|mdx}} Desktop 자체 프로세스의 작업 디렉터리     |
| `${userHome}`                | OS 사용자의 홈 디렉터리                          |
| `${pathSeparator}`, `${/}`   | OS 경로 구분자                                   |
| `${env:NAME}`                | 환경 변수 `NAME`(설정되어 있지 않으면 비어 있음) |

스캔 범위는 `command`, `args`, `options.cwd`, `options.env` 값, `options.shell`입니다. 그 외의 `${…}` 참조 — `${file}`, `${selectedText}`, `${lineNumber}`, `${config:*}`, `${command:*}`, `${input:*}`, `${defaultBuildTask}`, … — 는 작업을 숨깁니다. 작업공간이 열려 있지 않으면 `${workspaceFolder}` 또는 `${workspaceFolderBasename}`를 참조하는 작업은 해당 해석 단계에서 숨겨집니다.

## 작업이 숨겨지는 이유

구성한 그대로 실행할 수 없는 작업은 절반만 구성된 상태로 실행되는 대신 완전히 숨겨집니다. 작업은 팔레트에서 사라지며, 그 이유는 안정적인 규칙 id로 기록됩니다.

| 규칙                         | 이유                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `unsupportedVariable`        | 추측한 값을 치환하면 구성된 것과 다른 명령이 실행됩니다                        |
| `dependsOnObjectForm`        | 확장 타입의 종속성 항목은 실행할 수 없습니다                                   |
| `dependsOnBackground`        | 백그라운드 작업은 결코 끝나지 않으므로 체인이 기다릴 잘 정의된 대상이 없습니다 |
| `instancePolicy`             | 대화형 프롬프트만 존재합니다. 자동 정책은 인스턴스를 보이지 않게 종료시킵니다  |
| `cyclicDependency`           | 종속성 사이클은 결코 시작될 수 없습니다                                        |
| `transitiveHiddenDependency` | 숨겨졌거나 존재하지 않는 label에 종속됩니다 — 숨김이 전파됩니다                |
| `invalidTask`                | label이 없거나(완전히 제외됨) 병합 체인 어디에도 `command`가 없습니다          |

사라진 작업을 진단하려면 디버그 채널을 활성화하고 Desktop을 시작하세요 — 숨겨진 모든 작업이 규칙 id와 함께 로깅됩니다:

```bash
SPIRIT_DESKTOP_TASKS_DEBUG=1
```

로그 줄 형식은 `[desktop-host][tasks] hidden <file>#<label> rule=<id>`입니다.

## 작업 실행

작업은 팔레트에서 명시적으로 클릭할 때 시작됩니다. 신뢰된 워크스페이스에서만 `runOn: "folderOpen"`을 설정한 작업이 디렉터리를 열 때 자동으로 실행됩니다. 파일 저장이나 다른 이벤트로는 실행되지 않습니다. `worktreeCreated`는 계속 지원되지 않습니다.

- **종속성** — `dependsOn` label은 병합된 네임스페이스에서 해석됩니다. `dependsOrder: "parallel"`(기본값)에서는 모든 종속성이 각자의 터미널에서 각자의 프레젠테이션으로 함께 시작되며, 주 작업은 모든 종속성이 종료된 후에만 시작됩니다. 어떤 종속성이든 0이 아닌 코드로 종료되면 주 작업은 실행되지 않습니다 — VS Code와 동일한 실패 의미입니다. `"sequence"`에서는 종속성이 순서대로 하나씩 실행되고 첫 번째 0이 아닌 종료가 주 작업 시작 전에 체인을 중단합니다. 이미 실행 중인 종속성은 다시 시작하지 않고 기다립니다.
- **인스턴스 제한** — `runOptions.instanceLimit`의 기본값은 `1`입니다. 제한을 초과하여 다른 인스턴스를 시작하면 실행 중인 인스턴스와 경과 시간이 나열됩니다. 하나를 선택하고(첫 번째 인스턴스가 기본 선택됩니다) **교체**를 누르면 해당 인스턴스를 종료하고 새 실행을 시작하며, **취소**를 누르면 중단합니다. 설정된 제한을 초과하는 옵션은 없습니다.
- **폴더 열기 트리거** — `runOn: "folderOpen"`은 워크스페이스가 활성화될 때 작업을 자동으로 실행하지만, 신뢰된 워크스페이스(승인 후 또는 기존 신뢰 레코드가 있는 경우)에서만 실행됩니다. 거부된 워크스페이스에서는 절대 실행되지 않습니다. 신뢰 프롬프트를 승인하면 이 세션의 폴더 열기 작업이 바로 실행됩니다. 활성화당 최대 한 번만 트리거되며 `tasks.json`을 편집해도 다시 실행되지 않습니다. 작업이 이미 인스턴스 제한으로 실행 중이면 자동 실행은 조용히 건너뜁니다(대화 상자 없음).
- **터미널 재사용** — 종료된 작업의 터미널만 재사용됩니다. `panel: "shared"`와 `panel: "dedicated"`는 모두 이 작업의 유휴 터미널이 있으면 재사용하고(풀은 작업별로 구분됩니다) 없으면 새 탭을 엽니다. `panel: "new"`는 항상 새 탭을 엽니다.
- **에코** — `presentation.echo`(기본값 켜짐)를 사용하면 프로세스 출력 전에 명령줄이 터미널에 기록됩니다.
- **표시** — `always`(기본값)는 시작 시 도구 패널을 펼칩니다. `silent`는 시작 시 닫힌 상태를 유지하고 작업이 0이 아닌 코드로 종료될 때만 펼칩니다. `never`는 결코 자동으로 펼치지 않습니다. `focus: true`는 표시를 암시하며 추가로 키보드 포커스를 터미널로 이동합니다. VS Code와의 두 가지 차이점에 유의하세요: `reveal: "silent"`는 종료 코드가 0이 아닐 때만 펼칩니다({{product.name|mdx}}에는 problemMatcher 트리거 경로가 없습니다). 그리고 `presentation.revealProblems`는 전혀 효과가 없습니다 — 터미널 표시를 억제하지도 트리거하지도 않습니다.
- **지우기** — `presentation.clear`는 터미널을 재사용하는 재실행 전에 터미널을 지웁니다.
- **닫기** — `presentation.close`는 종료 코드와 관계없이 종료 시 탭을 자동으로 닫습니다.
- **터미널 이름 유지** — `presentation.preserveTerminalName`은 작업 label을 탭 제목으로 유지합니다. 그렇지 않으면 실행 중인 프로세스의 제목이 탭 제목으로 바뀝니다.
- **백그라운드** — `isBackground: true`는 작업을 끝나지 않는 작업으로 표시합니다. 이 작업의 종료는 실패가 아닌 사용자 종료로 계산됩니다(실패 표시 없음).
- **닫기 확인** — `promptOnClose: true`는 프로세스가 아직 살아 있는 탭을 닫을 때 확인을 요청합니다. 확인하면 프로세스가 종료됩니다.
- **숨겨진 작업** — `hide: true` 작업은 팔레트에 나타나지 않지만 `dependsOn` 종속성으로는 여전히 실행할 수 있습니다.

## 예시

완전한 `{{product.workspaceDataFolderName}}/tasks.json` 예시 — build → test → package 시퀀스 체인과 백그라운드 watch 작업:

```json
{
  "schemaVersion": 1,
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "pnpm",
      "args": ["run", "build"],
      "detail": "Production build",
      "icon": { "id": "hammer" }
    },
    {
      "label": "test",
      "command": "pnpm",
      "args": ["run", "test"],
      "dependsOn": ["build"],
      "dependsOrder": "sequence"
    },
    {
      "label": "package",
      "command": "bash",
      "args": ["${workspaceFolder}/scripts/package.sh"],
      "options": {
        "cwd": "${workspaceFolder}",
        "env": { "CHANNEL": "stable" }
      },
      "dependsOn": ["test"],
      "dependsOrder": "sequence",
      "presentation": { "clear": true, "panel": "shared" }
    },
    {
      "label": "watch",
      "command": "pnpm",
      "args": ["run", "watch"],
      "isBackground": true,
      "presentation": { "reveal": "silent", "panel": "dedicated" }
    }
  ]
}
```

- `test`는 `build`가 0으로 종료된 후에만 실행됩니다. 그 다음 `package`가 `test` 이후에 실행되며, 먼저 지워진 동일한 터미널을 재사용합니다.
- `package`는 실행 시점에 `${workspaceFolder}`를 해석하고 `CHANNEL`을 프로세스 환경에 추가합니다.
- `watch`는 방해가 되지 않습니다(`silent`는 0이 아닌 종료에서만 표시됩니다). 그리고 이 작업의 종료는 결코 실패로 계산되지 않습니다. 어떤 작업도 이 작업에 종속될 수 없다는 점에 유의하세요 — 백그라운드 작업을 가리키는 `dependsOn` 항목은 숨겨집니다.
