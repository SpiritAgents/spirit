확장은 `.spirit/extension.json`(Spirit 매니페스트 덤프)과 순수한 npm `package.json`이 있는 폴더입니다. Spirit은 확장을 사용자별, 호스트별로 설치하며 워크스페이스 `.spirit/` 아래에는 두지 않고, 각 설치를 가져온 마켓플레이스로 범위를 나눕니다: 설치 ID는 `(소스 id, name)`입니다.

| 호스트  | 경로                                                    |
| ------- | ------------------------------------------------------- |
| Desktop | `{spiritDataDir}/extensions/desktop/<sourceId>/<name>/` |
| CLI     | `{spiritDataDir}/extensions/cli/<sourceId>/<name>/`     |

이는 [Skills](../customize/skills.mdx)(`SKILL.md` 폴더), [MCP](../customize/mcp.mdx)(외부 서버), [Hooks](../customize/hooks.mdx)(`hooks.json` 스크립트)와는 다릅니다. `contributes.cli.hooks`는 CLI TUI 슬롯에 스타일을 지정하는 것으로 `hooks.json`이 아닙니다. 확장은 `mcp`, `hooks`, `skills` 또는 `rules`를 선언하면 같은 파일들을 *번들*로 포함할 수 있습니다.

설치된 각 확장에는 활성화 스위치가 있습니다. 비활성화하거나 제거하면 기여가 중단됩니다. 확장을 켜는 것은 선언된 MCP 서버, 에이전트 훅, 스킬, 규칙의 실행에 동의하는 것입니다.

마법사는 확장 이름(kebab-case), 표시 이름, 한 줄 설명, 스캐폴드할 기능을 묻습니다. `package.json`, `icon.svg`, `.spirit/extension.json`을 작성하고, 선택한 기능에 해당하는 파일(`skills/<name>/SKILL.md`, `rule.md`, `mcp.json`, `hooks.json`, `styles.css`, `index.mjs`)을 추가하며, 완료되면 바로 붙여넣을 수 있는 마켓플레이스 항목을 출력합니다.

스크립팅할 때는 모든 질문에 플래그가 있습니다: `[target-dir]`, `--name`, `--display-name`, `--description`, `--capabilities <csv>`, 그리고 확인을 건너뛰는 `--yes`.

결과는 언제든지 검증할 수 있습니다:

```bash
npx @spiritagent/extension-toolkit check ./my-extension
```

확장 디렉터리에는 `.spirit/extension.json`과 `package.json` 두 파일과 선언하는 기능 파일만 있으면 됩니다:

```text
my-extension/
  .spirit/
    extension.json        # Spirit 매니페스트 덤프(필수)
  package.json            # 순수 npm; `main`만 읽힘
  icon.svg                # 선택 사항; SVG만 가능, <script> 금지
  index.mjs               # 선택 사항; `main`이 참조하는 activate 엔트리
  mcp.json                # mcp 선언 시
  hooks.json              # hooks 선언 시(agent hooks)
  rule.md                 # rules 선언 시
  skills/<name>/SKILL.md  # skills 선언 시
  styles.css              # desktop CSS 선언 시(경로는 매니페스트에서 참조)
  cli-hooks.json          # CLI hooks 선언 시(경로는 매니페스트에서 참조)
```

`package.json`에는 Spirit 필드가 없습니다——`name`, `version`, `description`, `author`, `homepage`, `license`, `main`, `keywords`는 순수한 npm으로 유지됩니다. 호스트는 `main`만 읽으며, 이것이 [`activate`](#activate)의 모듈 엔트리입니다.

`.spirit/extension.json` 필드:

| 필드            | 설명                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | 필수. `1`이어야 함                                                                                                              |
| `name`          | 필수. kebab-case; 마켓플레이스 내 항목 id                                                                                       |
| `version`       | 필수. semver `major.minor.patch`; 프리릴리스 접미사는 지원되지 않음                                                             |
| `sourceId`      | 필수. 소유 마켓플레이스 소스 id. ZIP 패키지는 임의의 값을 자체 선언합니다(예: `"self-declared"`); 설치 파이프라인이 다시 씁니다 |
| `displayName`   | 필수. 사용자에게 표시되는 이름                                                                                                  |
| `description`   | 필수. 한 줄 요약                                                                                                                |
| `icon`          | 선택 사항. 확장 루트 기준 SVG 경로                                                                                              |
| `author`        | 선택 사항. `{ name, url? }`                                                                                                     |
| `categories`    | 선택 사항. 문자열 배열                                                                                                          |
| `manifest`      | 필수. 런타임 선언——아래 「`manifest`」 절 참조                                                                                  |

덤프에는 `source`나 큐레이션 필드(`reviewStatus`, `featured`)가 없습니다——이들은 마켓플레이스 항목에 속합니다.

선언된 파일은 존재하고 유효해야 합니다: `mcp`, `hooks`, `skills` 또는 `rules`를 선언했는데 해당 파일이 없으면 검증과 설치가 실패합니다. 존재하지만 선언되지 않은 파일은 무시되며 로드되지 않습니다.

</Tab>
</Tabs>

## `manifest`

`manifest` 객체는 확장의 런타임 선언입니다: 어떤 호스트를 지원하는지, 언제 활성화되는지, 무엇을 기여하는지. 마켓플레이스 항목에서 매니페스트는 마켓플레이스 운영자가 보증합니다. ZIP 패키지에서는 자체 선언이며 검토 확인 게이트를 거칩니다.

### 역량

| 값                   | 런타임                                                                      |
| -------------------- | --------------------------------------------------------------------------- |
| `tool-definitions`   | `contributes.tools`를 모델에 노출하려면 `tool-execution`과 함께 필요        |
| `tool-execution`     | 해당 도구를 실행하려면 `tool-definitions`와 함께 필요                       |
| `system-prompt`      | 시스템 프롬프트 조각을 기여하려면 `main`과 함께 필요                        |
| `desktop-ui`         | `contributes.desktop`와 함께 사용해야 합니다.                               |
| `cli-ui`             | `contributes.cli`와 함께 사용해야 합니다.                                   |
| `mcp`                | `contributes.mcp`와 함께 사용하며 패키지 루트 `mcp.json`을 로드합니다.      |
| `hooks`              | `contributes.hooks`와 함께 사용하며 패키지 루트 `hooks.json`을 로드합니다.  |
| `skills`             | `contributes.skills`와 함께 사용하며 `skills/<name>/SKILL.md`를 로드합니다. |
| `rules`              | `contributes.rules`와 함께 사용하며 패키지 루트 `rule.md`를 로드합니다.     |
| `approval-flow`      | 선언만 가능합니다. 승인은 각 도구의 `approvalMode`에 따라 결정됩니다.       |
| `questions-flow`     | 선언만 가능합니다. 질문은 `approvalMode: need-questions`에 따라 결정됩니다. |
| `settings`           | 선언만 가능합니다. 설정은 `settingsSchema`에서 가져옵니다.                  |
| `secret-storage`     | `secretSlots`와 함께 사용됩니다.                                            |
| `structured-results` | 선언만 가능합니다.                                                          |

`desktop-ui` / `cli-ui` / `mcp` / `hooks` / `skills` / `rules`와 해당 `contributes` 항목은 모두 있거나 모두 없어야 합니다.

### 활성화 이벤트

| 이벤트                 | 발생 시점                     |
| ---------------------- | ----------------------------- |
| `onStartup`            | 호스트 준비                   |
| `onExtensionInstalled` | 설치 완료 후                  |
| `onSessionOpened`      | 세션이 활성 상태가 됨         |
| `onSessionReset`       | 세션 재설정                   |
| `onUserMessage`        | 사용자가 메시지를 제출함      |
| `onToolCall`           | 도구가 실행되기 직전          |
| `onToolResult`         | 도구 결과를 사용할 수 있게 됨 |
| `onApprovalResolved`   | 승인 결정이 해결됨            |

호스트는 확장 프로그램이 이벤트를 나열하고 읽을 수 있는 `main`이 있을 때 `activate`를 호출합니다.

### `contributes.tools`

| 필드            | 설명                                                        |
| --------------- | ----------------------------------------------------------- |
| `name`          | 필수. `[a-z0-9]+(?:[._-][a-z0-9]+)*`                        |
| `description`   | 필수. 모델에 표시됩니다.                                    |
| `inputSchema`   | 필수. JSON Schema 객체                                      |
| `outputSchema`  | 선택 사항. JSON Schema 객체                                 |
| `approvalMode`  | 선택 사항. `allowed`, `need-approval` 또는 `need-questions` |
| `executionMode` | 선택 사항. `foreground` 또는 `background`                   |

모델은 `name`을 그대로 보지 않습니다. 호스트는 `extension__{id}__{tool}__{hash}`와 같은 호출 이름을 구성합니다.

### `contributes.desktop`

`desktop-ui`가 필요합니다.

| 필드           | 설명                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| `css[].path`   | 필수. 패키지 루트 기준 CSS 파일                                            |
| `css[].media`  | 선택 사항. CSS 미디어 쿼리                                                 |
| `settingsPage` | 선택 사항. `true`, `{}` 또는 `{ title }` — Desktop 설정 항목을 추가합니다. |

### `contributes.cli`

`cli-ui`가 필요합니다. `hooks`는 인라인 배열이 아닌 `path`를 포함한 객체입니다:

```json
{
  "hooks": { "path": "cli-hooks.json" }
}
```

파일은 `{ "hooks": [ ... ] }` 형식이어야 합니다.

| 필드      | 설명                                                                      |
| --------- | ------------------------------------------------------------------------- |
| `slot`    | 필수. 아래 슬롯 중 하나                                                   |
| `variant` | 선택 사항. `default`, `accented`, `muted`, `warning`, `success`, `danger` |
| `tokens`  | 선택 사항. `{ foreground?, border?, accent? }`                            |
| `prefix`  | 선택 사항. 문자열                                                         |
| `suffix`  | 선택 사항. 문자열                                                         |

슬롯: `message.user`, `message.assistant`, `message.tool`, `assistant.thinking`, `input.frame`, `bottom_form`, `bottom_form.section`, `slash_suggestions`, `approval.panel`, `questions.panel`.

토큰 역할: `default`, `primary`, `secondary`, `muted`, `accent`, `success`, `warning`, `danger`.

```json
{
  "hooks": [
    {
      "slot": "input.frame",
      "variant": "accented",
      "tokens": { "border": "accent" },
      "prefix": "[",
      "suffix": "]"
    }
  ]
}
```

### 번들 MCP, hooks, skills, rules

대응하는 capability가 필요합니다. `contributes.mcp`, `contributes.hooks`, `contributes.skills`, `contributes.rules`는 `true` 또는 `{}`입니다. 경로는 규약이며 사용자 지정 path는 허용되지 않습니다.

| 기여        | Capability | 파일                                                                                   |
| ----------- | ---------- | -------------------------------------------------------------------------------------- |
| MCP         | `mcp`      | 패키지 루트 `mcp.json` (사용자/워크스페이스 MCP와 동일한 schema)                       |
| Agent hooks | `hooks`    | 패키지 루트 `hooks.json` (agent hooks와 동일한 schema. `contributes.cli.hooks`가 아님) |
| Skills      | `skills`   | `skills/<name>/SKILL.md`                                                               |
| Rules       | `rules`    | 패키지 루트 `rule.md`                                                                  |

선언했는데 파일이 없거나 잘못된 경우 설치가 실패합니다. 선언되지 않은 파일은 무시되며 로드되지 않습니다.

상대 `command` / `cwd`는 확장 프로그램 루트 기준입니다. MCP stdio에서 `cwd`를 생략하면 확장 프로그램 루트가 기본값입니다.

확장 프로그램이 켜져 있을 때만 세션에 overlay되며 **설정 → MCPs | Hooks | Skills | Rules** 목록에는 나타나지 않습니다. 이름 충돌은 workspace > user > extension입니다.

### `settingsSchema`

| 필드           | 설명                                                   |
| -------------- | ------------------------------------------------------ |
| `key`          | 필수. 도구 이름과 동일한 패턴                          |
| `type`         | 필수. `string`, `boolean`, `number` 또는 `select`      |
| `title`        | 필수. UI 레이블                                        |
| `description`  | 선택 사항                                              |
| `placeholder`  | 선택 사항                                              |
| `required`     | 선택 사항. 부울                                        |
| `defaultValue` | 선택 사항. `type`과 일치해야 함                        |
| `options`      | `select`에 필수. `{ value, label, description? }` 배열 |

값은 `string`, `number`, `boolean` 또는 `null`입니다. `null`은 필수가 아닌 설정을 지웁니다.

### `secretSlots`

| 필드          | 설명            |
| ------------- | --------------- |
| `key`         | 필수            |
| `title`       | 필수            |
| `description` | 선택 사항       |
| `required`    | 선택 사항. 부울 |

Desktop은 OS 키링에 비밀을 저장합니다. CLI 데몬 경로에서는 `secrets.set` / `secrets.delete`를 사용하지 못할 수 있습니다.

## `activate`

`main`은 동적 `import`로 로드됩니다. 다음 중 하나를 내보내세요:

- `export function activate(ctx) { ... }`
- `export default function activate(ctx) { ... }`
- `export default { activate }`

### `ctx`

| 필드              | 설명                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `extension`       | `{ id, name, version, directoryPath, manifestPath, main }`                                         |
| `host`            | 호스트 API. Desktop은 `showMessageBox`를 구현합니다. CLI는 `{}`입니다.                             |
| `log`             | `(message: string) => void`                                                                        |
| `settings`        | `get(key)`, `getAll()`, `set(key, value)`, `setAll(values)`                                        |
| `secrets`         | `get(key)`, `has(key)`, `set(key, value)`, `delete(key)` — 키는 `secretSlots`에서 선언해야 합니다. |
| `activationEvent` | 선택 사항. `{ type, detail? }`                                                                     |

### 반환 값

객체를 반환하거나, 모듈에서 동일한 필드를 내보냅니다.

| 필드              | 설명                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| `tools`           | `Record<string, (ctx) => unknown>`. 키는 매니페스트 도구 이름입니다. |
| `invokeTool`      | `(ctx) => unknown`. `tools[name]` 대신 사용됩니다.                   |
| `systemPrompt`    | 정적 시스템 조각                                                     |
| `getSystemPrompt` | `() => string \| Promise<string>`. `systemPrompt` 대신 사용됩니다.   |
| `onEvent`         | `(event) => void`                                                    |
| `dispose`         | `() => void`. 제거 또는 재로드 시 호출됩니다.                        |

### 도구 핸들러 `ctx`

| 필드              | 설명                                                          |
| ----------------- | ------------------------------------------------------------- |
| `extension`       | `activate`와 동일한 런타임 정보                               |
| `host`            | 동일한 호스트 API                                             |
| `toolName`        | 매니페스트 도구 이름                                          |
| `arguments`       | 모델에서 온 객체                                              |
| `log`             | 동일한 로거                                                   |
| `settings`        | 동일한 설정 접근자                                            |
| `secrets`         | 동일한 비밀 접근자                                            |
| `toolCallId`      | 선택 사항                                                     |
| `questionsResult` | 선택 사항. `approvalMode`가 `need-questions`일 때 설정됩니다. |

`string` 결과는 그대로 전달됩니다. 다른 값은 `JSON.stringify(value, null, 2)`로 변환됩니다. `undefined`는 `""`가 됩니다.

### 데스크톱 `host.showMessageBox`

| 필드        | 설명                                                      |
| ----------- | --------------------------------------------------------- |
| `title`     | 필수. 문자열                                              |
| `message`   | 필수. 문자열                                              |
| `detail`    | 선택 사항. 문자열                                         |
| `buttons`   | 선택 사항. 문자열 배열                                    |
| `cancelId`  | 선택 사항. 숫자                                           |
| `defaultId` | 선택 사항. 숫자                                           |
| `noLink`    | 선택 사항. 불리언                                         |
| `type`      | 선택 사항. `none`, `info`, `error`, `question`, `warning` |

```js
export function activate(ctx) {
  return {
    systemPrompt: "Use lookup_item when the user asks for an item by id.",
    async invokeTool({ toolName, arguments: args, settings, secrets }) {
      if (toolName !== "lookup_item") {
        throw new Error(`Unknown tool: ${toolName}`);
      }
      const region = await settings.get("region");
      const token = await secrets.get("api_token");
      return { id: args.id, region, hasToken: Boolean(token) };
    },
    dispose() {
      ctx.log("example-extension disposed");
    },
  };
}
```

## ZIP으로 배포하기

확장 디렉터리를 공유 가능한 ZIP 형식(콘텐츠와 `.spirit/extension.json`)으로 패킹합니다:

```bash
npx @spiritagent/extension-toolkit pack ./my-extension
```

이 명령은 먼저 패키지를 검증한 다음 `<name>-<version>.zip`을 현재 디렉터리에 씁니다. 사용자는 **확장** 페이지 또는 `spirit extension import`로 ZIP을 가져오며, 개인 마켓플레이스에 등록됩니다. [확장](../customize/extensions.mdx)을 참조하세요.

## 원격 확장 마켓플레이스 운영하기

원격 확장 마켓플레이스는 `.spirit/marketplace.json` 인덱스를 제공하는 서비스 가능한 디렉터리입니다: Git 저장소, 정적 사이트 또는 로컬 디렉터리. 사용자는 `spirit extension marketplace add <url|path>` 또는 Desktop **확장** 페이지에서 추가한 다음 항목을 탐색하고 설치합니다.

<Tabs items={["템플릿 저장소", "수동으로 만들기"]}>
<Tab value="템플릿 저장소">

[Use this template](https://github.com/new?template_owner=SpiritAgents&template_name=extension-template)으로 `SpiritAgents/extension-template`에서 나만의 마켓플레이스 저장소를 만드세요.

템플릿에는 레지스트리 레이아웃, 두 개의 예제 확장, 그리고 모든 push와 pull request에서 레지스트리를 검증하는 CI가 포함되어 있습니다. 확장을 게시하려면:

1. `npm create @spiritagent/extension`으로 스캐폴드합니다.
2. 확장 폴더를 `extensions/`로 이동합니다.
3. 마법사가 출력한 레지스트리 항목을 `.spirit/marketplace.json`에 추가합니다.
4. 푸시합니다——사용자는 해당 Git URL로 마켓플레이스를 추가합니다.

</Tab>
<Tab value="수동으로 만들기">

마켓플레이스 루트는 인덱스와 확장별 콘텐츠 디렉터리를 담습니다:

```text
my-marketplace/
  .spirit/
    marketplace.json  # 인덱스
  extensions/
    my-extension/     # 콘텐츠 디렉터리(순수 npm 패키지 + 기능 파일)
      icon.svg
      package.json
      ...
```

`marketplace.json` 내의 상대 경로는 마켓플레이스 루트를 기준으로 해석되며 `..` 세그먼트나 절대 경로는 허용되지 않습니다.

항목 필드를 의미 그룹별로:

- **ID**——`name`(kebab-case; 항목 id), `version`(semver, 프리릴리스 없음), `source`: 로컬 콘텐츠의 경우 루트 상대 경로 문자열(예: `"./extensions/my-extension"`), 또는 `{ "source": "npm", "package": "@scope/name@1.0.0" }`로 정확한 npm 버전 고정(설치 시 packument의 SRI 해시로 무결성 검증).
- **표시**——`displayName`, `description`, `icon`(루트 상대 SVG 경로), `categories`, `author`.
- **선언**——`manifest`: 위 「`manifest`」 절에서 설명한 런타임 선언. 마켓플레이스가 이를 보증합니다; 패키지가 스스로 기능을 주장할 수는 없습니다.
- **큐레이션**——`featured`와 `reviewStatus`(`unverified` / `verified` / `revoked`).

레지스트리를 로컬에서 검증——오프라인: 스키마, kebab-case 이름, 프리릴리스 없는 semver, npm 소스 형식, 로컬 소스의 선언-콘텐츠 파일, 아이콘 규칙:

```bash
npx -y @spiritagent/extension-toolkit marketplace check .
```

검토 규율: 항목을 추가하거나 `version`을 변경하는 PR은 `reviewStatus: "unverified"`를 유지해야 합니다. 사람이 검토한 후 별도 커밋에서 `verified`로 승격하세요. 템플릿 저장소의 `.github/workflows/marketplace.yml`이 참조 구현입니다——PR 베이스를 기준으로 인덱스를 diff합니다.

</Tab>
</Tabs>

### 로컬 마켓플레이스

`.spirit/marketplace.json`이 있는 모든 로컬 디렉터리는 마켓플레이스로 추가할 수 있습니다——`spirit extension marketplace add <path>` 또는 Desktop의 **디스크에서 추가…**로. 로컬 마켓플레이스는 그 자리에서 읽히며 CI가 필요 없으므로 확장 작성자의 개발 루프가 됩니다: 편집, 재설치, 반복.
