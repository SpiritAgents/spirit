에이전트에게 리포지토리를 읽고 승인을 기다릴 수 있는 팀원에게 지시하듯 말하세요.

## 구체적으로 말하세요

파일 이름, 결과물, 건드리지 말아야 할 것을 명시하세요. 명확한 프롬프트는 작고 검토 가능한 diff를 만들어냅니다. 모호한 프롬프트는 탐색에 시간을 낭비합니다.

```txt
Read src/auth/session.ts and fix the expired-token refresh path.
Do not change the login form. Add a focused test next to the existing session tests.
```

## 컨텍스트 첨부

Desktop에서 작업이 특정 위치에 관한 것일 때 열린 파일, 선택 항목 또는 Browser 요소를 첨부하세요. 에이전트는 여전히 현재 내용을 보기 위해 파일을 읽어야 합니다 — 첨부 파일은 포인터일 뿐이며 [tools](./tools.mdx)의 대체품이 아닙니다.

## 먼저 모드를 선택하세요

- **Agent** — 변경 사항을 이미 알고 있을 때
- **Plan** — 편집 전에 서면 계획과 [질문](./ask-questions.mdx)을 원할 때
- **Ask** — 설명만 원할 때
- **Debug** — 버그를 재현할 수 있고 로그를 원할 때

[Modes](./modes.mdx)를 참조하세요.

## 승인이 제 역할을 하게 하세요

**기본** 승인에서는 에이전트가 편집이나 명령 실행 전에 멈춥니다. diff를 읽고 승인 또는 거부하세요. 루프를 신뢰하기 전에는 우회를 켜지 마세요. [Approvals](./approvals.mdx)를 참조하세요.

편집기의 인라인 완성(Tab)은 이 대화의 일부가 아닙니다. Settings → Tab에서 구성하세요.
