Эта страница проведет вас от новой установки до одного полезного изменения. Последующие страницы описывают каждого провайдера и хост; без этого пути этим страницам не за что зацепиться.

## 1. Установите Desktop или CLI

Выберите один хост. Они используют один и тот же локальный демон, поэтому вы можете добавить другой позже.

<Tabs items={["Desktop", "CLI"]}>
  <Tab value="Desktop">

Загрузите сборку для вашей платформы со [страницы загрузки](/en-US/download), затем откройте её.

- macOS: `.dmg` (Intel или Apple Silicon)
- Windows: установщик `.exe` (x64 или ARM64)
- Linux: `.AppImage` (x64 или ARM64)

Подробнее: [Установка Desktop](./install/desktop.mdx).

</Tab>
  <Tab value="CLI">

```bash
curl -fsSL https://spirit.dev/install | bash
```

```powershell
irm https://spirit.dev/install.ps1 | iex
```

Откройте новый терминал и выполните `spirit --version`. Подробнее: [Установка CLI](./install/cli.mdx).

</Tab>
</Tabs>

## 2. Откройте рабочую область

Агент читает и редактирует файлы в корне рабочей области. Откройте проект, который хотите изменить.

<Tabs items={["Desktop", "CLI"]}>
  <Tab value="Desktop">

Используйте **Открыть папку рабочей области** на боковой панели и выберите папку. Недавние рабочие области остаются в списке.

</Tab>
  <Tab value="CLI">

```bash
cd /path/to/your/project
spirit
```

TUI использует текущий каталог как рабочую область.

</Tab>
</Tabs>

## 3. Подключите одного провайдера

Вам нужен API-ключ от провайдера, которым вы уже пользуетесь. Spirit хранит этот ключ в системном хранилище ключей (`Spirit`).

<Tabs items={["Desktop", "CLI"]}>
  <Tab value="Desktop">

1. Откройте **Настройки → Модели**.
2. Выберите провайдера и следуйте мастеру подключения.
3. Вставьте ключ. Дополнительные поля (регион, сайт, конечная точка плана) появляются только тогда, когда они нужны этому провайдеру.
4. Выберите модель чата как активную модель.

</Tab>
  <Tab value="CLI">

В TUI выполните `/model add` и заполните форму. Вы также можете добавить модель из оболочки:

```bash
spirit model add
```

`SPIRIT_API_KEY` и `SPIRIT_API_BASE` переопределяют сохраненный ключ и базовый URL для этого процесса, когда нужен разовый запуск.

</Tab>
</Tabs>

## 4. Попросите о небольшом изменении, затем одобрите его

Оставайтесь в режиме **Agent** и **default** для утверждения при первом запуске. Попросите агента прочитать файл, который вы знаете, а затем внести небольшое очевидное изменение.

Пример:

```txt
Read README.md and add a one-line project summary at the top. Do not change anything else.
```

Агент прочитает файл, предложит изменение и будет ждать. Одобрите изменение файла (и любую команду оболочки) в подсказке. После завершения откройте файл и подтвердите изменение.

Это весь цикл: установка → рабочая область → один провайдер → чтение → редактирование → одобрение. Все остальное в этой документации основано на этом пути.
