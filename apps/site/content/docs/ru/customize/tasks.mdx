<Callout type="info">Только для Desktop.</Callout>

Задачи запускают предопределённые команды рабочей области из палитры команд {{product.name|mdx}} Desktop: откройте палитру (`Mod+Shift+P`), выберите **Рабочая область → Запустить задачу**, затем выберите задачу в списке второго уровня. Задача выполняется во вкладке терминала на панели инструментов справа. Группа **Рабочая область** появляется в палитре, только если существует хотя бы одна допустимая задача.

Задачи {{product.name|mdx}} — это собственная система, а не задачи VS Code. Она читает формат {{product.name|mdx}} на строгом JSON и, в качестве импорта для совместимости, `tasks.json` из VS Code — с чётко определённым подмножеством полей VS Code. Задача, которая не может выполняться в точности так, как настроена, полностью скрывается, а не запускается наполовину настроенной; см. [Почему задача скрыта](#почему-задача-скрыта).

## Файлы задач

Читаются три источника, в порядке убывания приоритета:

| Приоритет | Источник                         | Обязательный маркер  | Примечания                                                     |
| --------- | -------------------------------- | -------------------- | -------------------------------------------------------------- |
| 1         | `<workspace>/{{product.workspaceDataFolderName}}/tasks.json` | `"schemaVersion": 1` | Собственный формат {{product.name|mdx}}                                      |
| 2         | `<data dir>/tasks.json`          | `"schemaVersion": 1` | Пользовательский уровень, применяется к каждой рабочей области |
| 3         | `<workspace>/.vscode/tasks.json` | `"version": "2.0.0"` | Импорт для совместимости с VS Code, только чтение              |

Сканируется только корень рабочей области — вложенные каталоги не сканируются. `<data dir>` — это каталог данных {{product.name|mdx}} (например, `~/{{product.stable.userDataFolderName}}` на macOS). Файл, который отсутствует, недоступен для чтения, содержит недопустимый JSON или несёт неверный маркер, не добавляет задач.

Три файла отслеживаются в реальном времени; список в палитре обновляется автоматически при изменении любого из них.

Все три источника объединяются в одно пространство имён. Когда несколько источников определяют одинаковый `label`, побеждает источник с наивысшим приоритетом — как для списка в палитре, так и для ссылок `dependsOn`.

`.vscode/tasks.json` разбирается терпимо, потому что реальные файлы — это JSONC: допускаются комментарии `//` и `/* */` и висячие запятые. Собственные файлы {{product.name|mdx}} — строгий JSON: комментарий делает файл недопустимым.

## Доверие к рабочей области

Файлы задач рабочей области приходят вместе с репозиторием, поэтому это недоверенные данные: `{{product.workspaceDataFolderName}}/tasks.json` и `.vscode/tasks.json` загружаются только после вашего одобрения содержимого рабочей области. Пользовательский `tasks.json` (каталог данных {{product.name|mdx}}) неявно доверен и всегда загружается.

Когда {{product.name|mdx}} Desktop обнаруживает файлы задач рабочей области (или их изменение), он спрашивает один раз: в диалоге перечислены задачи, которые станут доступны, с их командами, а щелчок по записи открывает исходный файл. Если хуки рабочей области тоже требуют одобрения, оба списка появляются в одном объединённом диалоге.

- **Разрешить один раз** — задачи загружаются только в этой сессии.
- **Всегда доверять** — запоминается для этого точного содержимого файла.
- **Отклонить** — задачи рабочей области остаются недоступными; отказ запоминается для этого точного содержимого в этой сессии.

Редактирование любого из файлов спросит снова (одобрение привязано к хешу содержимого). Чтобы восстановиться после отказа, отредактируйте файл (спросят снова) или перезапустите приложение.

Этот барьер — структурная предпосылка автоматических триггеров: `runOn: "folderOpen"` запускается только после одобрения, а `worktreeCreated` остаётся отключённым.

## Поля

Поведение каждого поля, вычисляемое после слияния: значения по умолчанию уровня файла < блок ОС уровня файла < задача < блок ОС уровня задачи.

### Основные поля

| Поле                                         | Поведение      | Примечания                                                                                                                                                                                                                                                                             |
| -------------------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`                                      | Обязательное   | Элементы без непустой метки отбрасываются полностью — они никогда не попадают ни в меню, ни в граф зависимостей                                                                                                                                                                        |
| `type`                                       | Поддерживается | `shell` (по умолчанию) или `process`. Любая другая строка (`npm`, `grunt`, …) — это запись, настроенная расширением, и она полностью игнорируется: не скрывается, не отображается, соседние задачи не затрагиваются                                                                    |
| `command`                                    | Поддерживается | `string`, `string[]` или `{ value, quoting }`. Задача, у которой после слияния отсутствует команда, скрывается — в том числе для задач `shell` (строже, чем VS Code)                                                                                                                   |
| `args`                                       | Поддерживается | Массив из `string` или `{ value, quoting }`                                                                                                                                                                                                                                            |
| `quoting`                                    | Поддерживается | `escape`, `strong` (по умолчанию) или `weak`; недопустимые значения откатываются к `strong`. Применяется к `args` и объектной форме `{ value, quoting }`; значение `command` в виде простой строки передаётся в оболочку дословно, поэтому может содержать исходный синтаксис оболочки |
| `options.cwd`                                | Поддерживается | Рабочий каталог процесса                                                                                                                                                                                                                                                               |
| `options.env`                                | Поддерживается | Дополнительные переменные окружения, объединяемые поверх окружения хоста                                                                                                                                                                                                               |
| `options.shell`                              | Поддерживается | `{ executable, args }` — оболочка, используемая для задач `shell` вместо терминальной оболочки по умолчанию                                                                                                                                                                            |
| `windows` / `osx` / `linux` (уровень задачи) | Поддерживается | Переопределения `{ command, args, options }` для текущей ОС.                                                                                                                                                                                                                           |
| `windows` / `osx` / `linux` (уровень файла)  | Поддерживается | Та же форма, действует как слой значений по умолчанию, специфичных для ОС, для каждой задачи в файле                                                                                                                                                                                   |
| Значения по умолчанию уровня файла           | Поддерживается | Только `command`, `args`, `options`, `type`, `isBackground`, `promptOnClose`, `presentation` могут выступать значениями по умолчанию уровня файла.                                                                                                                                     |
| `isBackground`                               | Поддерживается | Завершение засчитывается как прекращение пользователем, никогда как сбой. Другая задача, зависящая от неё, скрывается (см. ниже)                                                                                                                                                       |
| `promptOnClose`                              | Поддерживается | Закрытие вкладки, пока процесс жив, запрашивает подтверждение                                                                                                                                                                                                                          |
| `dependsOn`                                  | Поддерживается | Строка метки или массив строк меток. Объектная форма (`{ "type": … }`, `{ "task": … }`) скрывает задачу                                                                                                                                                                                |
| `dependsOrder`                               | Поддерживается | `parallel` (по умолчанию) или `sequence`                                                                                                                                                                                                                                               |
| `detail`                                     | Поддерживается | Показывается рядом с меткой в списке палитры                                                                                                                                                                                                                                           |
| `icon.id`                                    | Поддерживается | Значок меню: сначала {{product.name|mdx}} Icons, затем Lucide, с глифом терминала в качестве запасного варианта                                                                                                                                                                                      |
| `icon.color`                                 | Игнорируется   | Чисто декоративное                                                                                                                                                                                                                                                                     |
| `hide`                                       | Поддерживается | Скрыта из списка палитры, но по-прежнему разрешается — задача может запускаться как зависимость `dependsOn`                                                                                                                                                                            |

### Параметры запуска

| Поле                           | Поведение      | Примечания                                                                                             |
| ------------------------------ | -------------- | ------------------------------------------------------------------------------------------------------ |
| `runOptions.reevaluateOnRerun` | Поддерживается | По умолчанию `true`. `false` кэширует первое разрешение для последующих перезапусков                   |
| `runOptions.runOn`             | Ограничено     | Поддерживаются `default` и `folderOpen`; `worktreeCreated` скрывает задачу                             |
| `runOptions.instanceLimit`     | Поддерживается | По умолчанию `1`. Превышение лимита открывает диалог (см. [Запуск задач](#запуск-задач))               |
| `runOptions.instancePolicy`    | Ограничено     | Поддерживается только `prompt`. `terminateNewest`, `terminateOldest`, `warn`, `silent` скрывают задачу |

### Представление

| Поле                                | Поведение      | Примечания                                                                            |
| ----------------------------------- | -------------- | ------------------------------------------------------------------------------------- |
| `presentation.echo`                 | Поддерживается | Записывает командную строку в терминал перед выводом процесса                         |
| `presentation.reveal`               | Поддерживается | `always` (по умолчанию), `silent` или `never` — см. [Запуск задач](#запуск-задач)     |
| `presentation.focus`                | Поддерживается | Подразумевает раскрытие и перемещает фокус клавиатуры в терминал                      |
| `presentation.panel`                | Поддерживается | `shared` (по умолчанию), `dedicated` или `new` — политика переиспользования терминала |
| `presentation.clear`                | Поддерживается | Очищает терминал перед перезапуском, который его переиспользует                       |
| `presentation.close`                | Поддерживается | Автоматически закрывает вкладку при завершении процесса                               |
| `presentation.preserveTerminalName` | Поддерживается | Сохраняет метку задачи как заголовок вкладки вместо заголовка процесса                |
| `presentation.showReuseMessage`     | Игнорируется   | Чисто декоративное                                                                    |
| `presentation.group`                | Игнорируется   | Группировка терминалов выходит за рамки                                               |

### Игнорируемые поля

Наличие этих полей никогда не скрывает задачу: `problemMatcher` (любая форма, на любом уровне), `presentation.revealProblems`, `group` (группировка build/test), `icon.color`, `presentation.showReuseMessage`, `presentation.group`, `inAgents`. Массив `inputs` уровня файла просто не читается — но _ссылка_ `${input:*}` внутри задачи скрывает эту задачу (см. [Переменные](#переменные)).

## Переменные

Поддерживаемые ссылки, подставляемые при разрешении задачи:

| Переменная                   | Значение                                             |
| ---------------------------- | ---------------------------------------------------- |
| `${workspaceFolder}`         | Путь к корню рабочей области                         |
| `${workspaceFolderBasename}` | Имя корневой папки рабочей области                   |
| `${cwd}`                     | Рабочий каталог собственного процесса {{product.name|mdx}} Desktop |
| `${userHome}`                | Домашний каталог пользователя ОС                     |
| `${pathSeparator}`, `${/}`   | Разделитель путей ОС                                 |
| `${env:NAME}`                | Переменная окружения `NAME` (пустая, если не задана) |

Сканирование охватывает `command`, `args`, `options.cwd`, значения `options.env` и `options.shell`. Любая другая ссылка `${…}` — `${file}`, `${selectedText}`, `${lineNumber}`, `${config:*}`, `${command:*}`, `${input:*}`, `${defaultBuildTask}`, … — скрывает задачу. Когда рабочая область не открыта, задачи, ссылающиеся на `${workspaceFolder}` или `${workspaceFolderBasename}`, скрываются на этом проходе разрешения.

## Почему задача скрыта

Задача, которая не может выполняться в точности так, как настроена, полностью скрывается, а не запускается наполовину настроенной. Задача исчезает из палитры; причина фиксируется со стабильным идентификатором правила.

| Правило                      | Обоснование                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| `unsupportedVariable`        | Подстановка угаданного значения запустила бы команду, отличную от настроенной             |
| `dependsOnObjectForm`        | Типизированные расширениями записи зависимостей не являются запускаемыми                  |
| `dependsOnBackground`        | Фоновая задача никогда не завершается, поэтому у цепочки нет чётко определённого ожидания |
| `instancePolicy`             | Существует только интерактивный запрос; тихие политики завершали бы экземпляры незаметно  |
| `cyclicDependency`           | Цикл зависимостей никогда не смог бы стартовать                                           |
| `transitiveHiddenDependency` | Зависит от метки, которая сама скрыта или не существует — скрытие распространяется        |
| `invalidTask`                | Нет метки (отбрасывается полностью) или нет `command` нигде в цепочке слияния             |

Чтобы диагностировать исчезнувшую задачу, запустите Desktop с включённым отладочным каналом — каждая скрытая задача протоколируется со своим идентификатором правила:

```bash
SPIRIT_DESKTOP_TASKS_DEBUG=1
```

Строка журнала имеет вид `[desktop-host][tasks] hidden <file>#<label> rule=<id>`.

## Запуск задач

Задачи стартуют по явному щелчку в палитре; только в доверенных рабочих областях задачи с `runOn: "folderOpen"` также запускаются автоматически при открытии папки. При сохранении файла или любом другом событии ничто не запускается. `worktreeCreated` по-прежнему не поддерживается.

- **Зависимости** — метки `dependsOn` разрешаются в объединённом пространстве имён. При `dependsOrder: "parallel"` (по умолчанию) все зависимости стартуют вместе, каждая в своём терминале со своим представлением, а основная задача стартует только после завершения каждой зависимости; если любая зависимость завершается с ненулевым кодом, основная задача не запускается — та же семантика сбоев, что в VS Code. При `"sequence"` зависимости выполняются по одной по порядку, и первый ненулевой код завершения прерывает цепочку до старта основной задачи. Уже запущенная зависимость ожидается, а не перезапускается.
- **Лимит экземпляров** — `runOptions.instanceLimit` по умолчанию равен `1`. Запуск ещё одного экземпляра сверх лимита показывает список запущенных экземпляров с временем их работы; выберите один (первый выбран по умолчанию) и нажмите **Заменить**, чтобы завершить его и начать новый запуск, или **Отмена**. Превысить настроенный лимит нельзя.
- **Триггер открытия папки** — `runOn: "folderOpen"` запускает задачу автоматически при активации рабочей области, но только в доверенных областях (после одобрения или при наличии записи доверия); в отклонённой области она никогда не запускается. После одобрения запроса доверия задачи открытия папки этой сессии запускаются сразу. Триггер срабатывает не более одного раза за активацию — редактирование `tasks.json` ничего не запускает повторно — а если задача уже выполняется на лимите экземпляров, автоматический запуск молча пропускается (без диалога).
- **Переиспользование терминала** — переиспользуются только терминалы завершённых задач. `panel: "shared"` и `panel: "dedicated"` оба переиспользуют собственный простаивающий терминал этой задачи, когда он есть (пул ведётся по задачам), и открывают новую вкладку в противном случае; `panel: "new"` всегда открывает новую вкладку.
- **Эхо** — при `presentation.echo` (по умолчанию включено) командная строка записывается в терминал перед выводом процесса.
- **Раскрытие** — `always` (по умолчанию) разворачивает панель инструментов при запуске; `silent` держит её закрытой при запуске и разворачивает только при ненулевом завершении задачи; `never` никогда не разворачивает автоматически. `focus: true` подразумевает раскрытие и дополнительно перемещает фокус клавиатуры в терминал. Обратите внимание на два отличия от VS Code: `reveal: "silent"` раскрывает панель только при ненулевом коде завершения (в {{product.name|mdx}} нет пути срабатывания через problem matcher), а `presentation.revealProblems` не оказывает никакого эффекта — не подавляет и не вызывает раскрытие терминала.
- **Очистка** — `presentation.clear` очищает терминал перед перезапуском, который его переиспользует.
- **Закрытие** — `presentation.close` автоматически закрывает вкладку при завершении, независимо от кода завершения.
- **Сохранение имени терминала** — `presentation.preserveTerminalName` сохраняет метку задачи как заголовок вкладки; иначе его заменяет заголовок запущенного процесса.
- **Фоновая** — `isBackground: true` помечает задачу как никогда не завершающуюся; её завершение засчитывается как прекращение пользователем, никогда как сбой (без раскрытия при сбое).
- **Подтверждение закрытия** — `promptOnClose: true` запрашивает подтверждение при закрытии вкладки, чей процесс ещё жив; подтверждение завершает процесс.
- **Скрытые задачи** — задачи с `hide: true` никогда не появляются в палитре, но по-прежнему могут запускаться как зависимости `dependsOn`.

## Пример

Полный `{{product.workspaceDataFolderName}}/tasks.json` — последовательная цепочка build → test → package плюс фоновая задача watch:

```json
{
  "schemaVersion": 1,
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "pnpm",
      "args": ["run", "build"],
      "detail": "Production build",
      "icon": { "id": "hammer" }
    },
    {
      "label": "test",
      "command": "pnpm",
      "args": ["run", "test"],
      "dependsOn": ["build"],
      "dependsOrder": "sequence"
    },
    {
      "label": "package",
      "command": "bash",
      "args": ["${workspaceFolder}/scripts/package.sh"],
      "options": {
        "cwd": "${workspaceFolder}",
        "env": { "CHANNEL": "stable" }
      },
      "dependsOn": ["test"],
      "dependsOrder": "sequence",
      "presentation": { "clear": true, "panel": "shared" }
    },
    {
      "label": "watch",
      "command": "pnpm",
      "args": ["run", "watch"],
      "isBackground": true,
      "presentation": { "reveal": "silent", "panel": "dedicated" }
    }
  ]
}
```

- `test` запускается только после того, как `build` завершается с нулевым кодом; затем `package` запускается после `test`, переиспользуя тот же терминал, предварительно очищенный.
- `package` разрешает `${workspaceFolder}` во время выполнения и добавляет `CHANNEL` в окружение процесса.
- `watch` не мешается (`silent` раскрывает только при ненулевом завершении), и её завершение никогда не засчитывается как сбой. Обратите внимание: ничто не может от неё зависеть — запись `dependsOn`, указывающая на фоновую задачу, скрывается.
