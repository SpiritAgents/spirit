Расширение — это папка с `.spirit/extension.json` — дампом манифеста Spirit — рядом с чисто npm-ным `package.json`. Spirit устанавливает расширения для каждого пользователя и каждого хоста отдельно, а не в каталог `.spirit/` рабочей области, и ограничивает каждую установку маркетплейсом-источником: идентичность установки — `(id источника, name)`.

| Хост    | Путь                                                    |
| ------- | ------------------------------------------------------- |
| Desktop | `{spiritDataDir}/extensions/desktop/<sourceId>/<name>/` |
| CLI     | `{spiritDataDir}/extensions/cli/<sourceId>/<name>/`     |

Это отличается от [Skills](../customize/skills.mdx) (папки `SKILL.md`), [MCP](../customize/mcp.mdx) (внешние серверы) и [Hooks](../customize/hooks.mdx) (скрипты `hooks.json`). `contributes.cli.hooks` стилизует слоты TUI CLI. Это не `hooks.json`. Расширение всё же может _поставлять_ те же файлы, если объявляет `mcp`, `hooks`, `skills` или `rules`.

У каждого установленного расширения есть переключатель включения. Отключите или удалите его, чтобы остановить его вклады. Включение расширения — это согласие на запуск объявленных им MCP-серверов, хуков агента, навыков и правил.

Мастер спрашивает имя расширения (kebab-case), отображаемое имя, однострочное описание и возможности для каркаса. Он записывает `package.json`, `icon.svg` и `.spirit/extension.json`, плюс файлы выбранных возможностей (`skills/<name>/SKILL.md`, `rule.md`, `mcp.json`, `hooks.json`, `styles.css`, `index.mjs`), а в конце выводит готовую запись маркетплейса для вставки.

Для скриптов у каждого вопроса есть флаг: `[target-dir]`, `--name`, `--display-name`, `--description`, `--capabilities <csv>` и `--yes` для пропуска подтверждения.

Проверить результат можно в любой момент:

```bash
npx @spiritagent/extension-toolkit check ./my-extension
```

Каталогу расширения нужны только два файла — `.spirit/extension.json` и `package.json` — плюс файлы объявленных возможностей:

```text
my-extension/
  .spirit/
    extension.json        # дамп манифеста Spirit (обязательно)
  package.json            # чисто npm; читается только `main`
  icon.svg                # необязательно; только SVG, без <script>
  index.mjs               # необязательно; вход activate, на который ссылается `main`
  mcp.json                # при объявлении mcp
  hooks.json              # при объявлении hooks (хуки агента)
  rule.md                 # при объявлении rules
  skills/<name>/SKILL.md  # при объявлении skills
  styles.css              # при объявлении CSS для desktop (путь указан в манифесте)
  cli-hooks.json          # при объявлении хуков CLI (путь указан в манифесте)
```

`package.json` не несёт полей Spirit — `name`, `version`, `description`, `author`, `homepage`, `license`, `main`, `keywords` остаются чисто npm. Хост читает только `main`, вход модуля [`activate`](#activate).

Поля `.spirit/extension.json`:

| Поле            | Описание                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | Обязательно. Должно быть `1`                                                                                                                                        |
| `name`          | Обязательно. kebab-case; id записи внутри маркетплейса                                                                                                              |
| `version`       | Обязательно. Semver `major.minor.patch`; суффиксы предварительных версий не поддерживаются                                                                          |
| `sourceId`      | Обязательно. Id источника-маркетплейса-владельца. ZIP-пакеты самодекларируют любое значение (например, `"self-declared"`); установочный конвейер перезаписывает его |
| `displayName`   | Обязательно. Видимое пользователю имя                                                                                                                               |
| `description`   | Обязательно. Однострочное описание                                                                                                                                  |
| `icon`          | Необязательно. Путь к SVG относительно корня расширения                                                                                                             |
| `author`        | Необязательно. `{ name, email?, url? }` или строка в стиле npm `"Name <email> (url)"`                                                                               |
| `category`      | Необязательно. Одна строка                                                                                                                                          |
| `keywords`      | Необязательно. Массив строк с поисковыми ключевыми словами                                                                                                          |
| `homepage`      | Необязательно. URL проекта                                                                                                                                          |
| `manifest`      | Обязательно. Декларация времени выполнения — см. раздел «`manifest`»                                                                                                |

Дамп не несёт ни `source`, ни полей кураторства (`reviewStatus`, `featured`) — они принадлежат записи маркетплейса.

Объявленные файлы должны существовать и быть корректными: объявление `mcp`, `hooks`, `skills` или `rules` без соответствующего файла проваливает проверку и установку. Присутствующие, но не объявленные файлы игнорируются и никогда не загружаются.

## `manifest`

Объект `manifest` — это декларация времени выполнения расширения: какие хосты оно поддерживает, когда активируется и что вносит. В записи маркетплейса манифест подтверждён оператором маркетплейса; в ZIP-пакете он самодекларируем и контролируется подтверждением проверки.

### Возможности

| Значение             | Среда выполнения                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------- |
| `tool-definitions`   | Требуется с `tool-execution` для предоставления `contributes.tools` модели                |
| `tool-execution`     | Требуется с `tool-definitions` для запуска этих инструментов                              |
| `system-prompt`      | Требуется с `main` для добавления фрагмента системного промпта                            |
| `desktop-ui`         | Должен использоваться вместе с `contributes.desktop`                                      |
| `cli-ui`             | Должен использоваться вместе с `contributes.cli`                                          |
| `mcp`                | Должен использоваться вместе с `contributes.mcp`; загружает `mcp.json` в корне пакета     |
| `hooks`              | Должен использоваться вместе с `contributes.hooks`; загружает `hooks.json` в корне пакета |
| `skills`             | Должен использоваться вместе с `contributes.skills`; загружает `skills/<name>/SKILL.md`   |
| `rules`              | Должен использоваться вместе с `contributes.rules`; загружает `rule.md` в корне пакета    |
| `approval-flow`      | Только объявлено. Одобрение определяется параметром `approvalMode` каждого инструмента    |
| `questions-flow`     | Только объявлено. Вопросы определяются параметром `approvalMode: need-questions`          |
| `settings`           | Только объявлено. Настройки берутся из `settingsSchema`                                   |
| `secret-storage`     | Используется с `secretSlots`                                                              |
| `structured-results` | Только объявлено                                                                          |

`desktop-ui` / `cli-ui` / `mcp` / `hooks` / `skills` / `rules` и соответствующая запись `contributes` должны либо присутствовать оба, либо отсутствовать оба.

### События активации

| Событие                | Когда срабатывает                 |
| ---------------------- | --------------------------------- |
| `onStartup`            | Прогрев хоста                     |
| `onExtensionInstalled` | После завершения установки        |
| `onSessionOpened`      | Сеанс становится активным         |
| `onSessionReset`       | Сброс сеанса                      |
| `onUserMessage`        | Пользователь отправляет сообщение |
| `onToolCall`           | Инструмент собирается запуститься |
| `onToolResult`         | Результат инструмента доступен    |
| `onApprovalResolved`   | Решение об одобрении принято      |

Хост вызывает `activate`, когда расширение перечисляет событие и имеет читаемый `main`.

### `contributes.tools`

| Поле            | Описание                                                       |
| --------------- | -------------------------------------------------------------- |
| `name`          | Обязательно. `[a-z0-9]+(?:[._-][a-z0-9]+)*`                    |
| `description`   | Обязательно. Показывается модели                               |
| `inputSchema`   | Обязательно. Объект JSON Schema                                |
| `outputSchema`  | Необязательно. Объект JSON Schema                              |
| `approvalMode`  | Необязательно. `allowed`, `need-approval` или `need-questions` |
| `executionMode` | Необязательно. `foreground` или `background`                   |

Модель не видит `name` как есть. Хост создаёт имя вызова, например, `extension__{id}__{tool}__{hash}`.

### `contributes.desktop`

Требует `desktop-ui`.

| Поле           | Описание                                                                           |
| -------------- | ---------------------------------------------------------------------------------- |
| `css[].path`   | Обязательно. CSS-файл относительно корня пакета                                    |
| `css[].media`  | Необязательно. CSS media query                                                     |
| `settingsPage` | Необязательно. `true`, `{}` или `{ title }` — добавляет запись в настройки Desktop |
| `views[].id`   | Обязательно. kebab-case, уникален в расширении |
| `views[].path` | Обязательно. Предкомпилированный однофайловый ESM (`.js` / `.mjs`) относительно корня пакета. Хост не компилирует TSX. Относительные import дают 404 — протокол отдаёт только этот файл. |
| `views[].title` | Необязательно. Заголовок диалога |
| `views[].width` | Необязательно. Ширина диалога |
| `views[].height` | Необязательно. Максимальная высота. Пропуск — высота по содержимому. Если view выше, iframe прокручивается. |
| `views[].chrome` | Необязательно. Оформление диалога: `default` (заголовок + закрыть), `close-only` (скрыть заголовок, оставить закрыть) или `none` (скрыть оба). Пропуск равносилен `default`. |

Экспорт по умолчанию: `export default function View({ params, close })`. `close(result)` завершает view. Хост внедряет React и `@spirit/desktop-ui`.

### `contributes.cli`

Требует `cli-ui`. `hooks` — это объект с `path`, а не встроенный массив:

```json
{
  "hooks": { "path": "cli-hooks.json" }
}
```

Файл должен быть `{ "hooks": [ ... ] }`.

| Поле      | Описание                                                                      |
| --------- | ----------------------------------------------------------------------------- |
| `slot`    | Обязательно. Один из слотов ниже                                              |
| `variant` | Необязательно. `default`, `accented`, `muted`, `warning`, `success`, `danger` |
| `tokens`  | Необязательно. `{ foreground?, border?, accent? }`                            |
| `prefix`  | Необязательно. Строка                                                         |
| `suffix`  | Необязательно. Строка                                                         |

Слоты: `message.user`, `message.assistant`, `message.tool`, `assistant.thinking`, `input.frame`, `bottom_form`, `bottom_form.section`, `slash_suggestions`, `approval.panel`, `questions.panel`.

Роли токенов: `default`, `primary`, `secondary`, `muted`, `accent`, `success`, `warning`, `danger`.

```json
{
  "hooks": [
    {
      "slot": "input.frame",
      "variant": "accented",
      "tokens": { "border": "accent" },
      "prefix": "[",
      "suffix": "]"
    }
  ]
}
```

### Встроенные MCP, hooks, skills и rules

Требуют соответствующую capability. `contributes.mcp`, `contributes.hooks`, `contributes.skills` и `contributes.rules` равны `true` или `{}`. Пути фиксированные; свои пути задавать нельзя.

| Вклад       | Capability | Файл                                                                                         |
| ----------- | ---------- | -------------------------------------------------------------------------------------------- |
| MCP         | `mcp`      | `mcp.json` в корне пакета (та же схема, что у пользовательского/рабочего MCP)                |
| Agent hooks | `hooks`    | `hooks.json` в корне пакета (та же схема, что у agent hooks; это не `contributes.cli.hooks`) |
| Skills      | `skills`   | `skills/<name>/SKILL.md`                                                                     |
| Rules       | `rules`    | `rule.md` в корне пакета                                                                     |

Объявлено, но файл отсутствует или некорректен — установка отклоняется. Необъявленные файлы игнорируются и никогда не загружаются.

Относительные `command` и `cwd` считаются от корня расширения. Если у MCP stdio нет `cwd`, по умолчанию используется корень расширения.

Эти вклады попадают в сессию при включённом расширении и **не** появляются в **Настройки → MCPs | Hooks | Skills | Rules**. При конфликте имён: workspace > user > extension.

Во время `tools/call` встроенный MCP может отправить `spirit/ui/open` (`{ viewId, params }`), если клиент объявил `experimental["spirit/ui"]`. Spirit открывает только view того же расширения из `contributes.desktop.views`. Пользовательский и workspace MCP отклоняются. Диалог блокирует этот вызов; `close(result)` возвращается в том же запросе. Хост без окна отвечает `{ "kind": "unavailable", "reason": "host-has-no-ui" }` — инструмент должен деградировать.

### `settingsSchema`

| Поле           | Описание                                                          |
| -------------- | ----------------------------------------------------------------- |
| `key`          | Обязательно. Тот же шаблон, что и для имён инструментов           |
| `type`         | Обязательно. `string`, `boolean`, `number` или `select`           |
| `title`        | Обязательно. Ярлык интерфейса                                     |
| `description`  | Необязательно                                                     |
| `placeholder`  | Необязательно                                                     |
| `required`     | Необязательно. Логическое значение                                |
| `defaultValue` | Необязательно. Должно соответствовать `type`                      |
| `options`      | Обязательно для `select`. Массив `{ value, label, description? }` |

Значения — `string`, `number`, `boolean` или `null`. `null` очищает необязательную настройку.

### `secretSlots`

| Поле          | Описание                           |
| ------------- | ---------------------------------- |
| `key`         | Обязательно                        |
| `title`       | Обязательно                        |
| `description` | Необязательно                      |
| `required`    | Необязательно. Логическое значение |

Desktop хранит секреты в системной связке ключей. В режиме демона CLI `secrets.set` / `secrets.delete` могут быть недоступны.

## `activate`

`main` загружается с помощью динамического `import`. Экспортируйте одно из:

- `export function activate(ctx) { ... }`
- `export default function activate(ctx) { ... }`
- `export default { activate }`

### `ctx`

| Поле              | Описание                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| `extension`       | `{ id, name, version, directoryPath, manifestPath, main }`                                             |
| `host`            | API хоста. Desktop реализует `showMessageBox` и `ui.open` / `ui.close`. CLI — `{}`                      |
| `log`             | `(message: string) => void`                                                                            |
| `settings`        | `get(key)`, `getAll()`, `set(key, value)`, `setAll(values)`                                            |
| `secrets`         | `get(key)`, `has(key)`, `set(key, value)`, `delete(key)` — ключи должны быть объявлены в `secretSlots` |
| `activationEvent` | Необязательно. `{ type, detail? }`                                                                     |

### Возвращаемое значение

Верните объект или экспортируйте те же поля из модуля.

| Поле              | Описание                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `tools`           | `Record<string, (ctx) => unknown>`. Ключи — имена инструментов манифеста                 |
| `invokeTool`      | `(ctx) => unknown`. Используется вместо `tools[name]`, если присутствует                 |
| `systemPrompt`    | Статический фрагмент системного промпта                                                  |
| `getSystemPrompt` | `() => string \| Promise<string>`. Используется вместо `systemPrompt`, если присутствует |
| `onEvent`         | `(event) => void`                                                                        |
| `dispose`         | `() => void`. Вызывается при удалении или перезагрузке                                   |

### Контекст обработчика инструмента `ctx`

| Поле              | Описание                                                                             |
| ----------------- | ------------------------------------------------------------------------------------ |
| `extension`       | Та же информация о времени выполнения, что и в `activate`                            |
| `host`            | Тот же хост API                                                                      |
| `toolName`        | Имя инструмента из манифеста                                                         |
| `arguments`       | Объект из модели                                                                     |
| `log`             | Тот же логгер                                                                        |
| `settings`        | Тот же доступ к настройкам                                                           |
| `secrets`         | Тот же доступ к секретам                                                             |
| `toolCallId`      | Необязательно                                                                        |
| `questionsResult` | Необязательно. Устанавливается, когда `approvalMode` имеет значение `need-questions` |

Результат `string` передается как есть. Другие значения — `JSON.stringify(value, null, 2)`. `undefined` превращается в `""`.

### Desktop `host.showMessageBox`

| Поле        | Описание                                                      |
| ----------- | ------------------------------------------------------------- |
| `title`     | Обязательно. Строка                                           |
| `message`   | Обязательно. Строка                                           |
| `detail`    | Необязательно. Строка                                         |
| `buttons`   | Необязательно. Массив строк                                   |
| `cancelId`  | Необязательно. Число                                          |
| `defaultId` | Необязательно. Число                                          |
| `noLink`    | Необязательно. Логическое значение                            |
| `type`      | Необязательно. `none`, `info`, `error`, `question`, `warning` |

```js
export function activate(ctx) {
  return {
    systemPrompt: "Use lookup_item when the user asks for an item by id.",
    async invokeTool({ toolName, arguments: args, settings, secrets }) {
      if (toolName !== "lookup_item") {
        throw new Error(`Unknown tool: ${toolName}`);
      }
      const region = await settings.get("region");
      const token = await secrets.get("api_token");
      return { id: args.id, region, hasToken: Boolean(token) };
    },
    dispose() {
      ctx.log("example-extension disposed");
    },
  };
}
```

## Распространение в виде ZIP

Упакуйте каталог расширения в распространяемый формат ZIP (содержимое плюс `.spirit/extension.json`):

```bash
npx @spiritagent/extension-toolkit pack ./my-extension
```

Команда сначала проверяет пакет и записывает `<name>-<version>.zip` в текущий каталог. Пользователи импортируют ZIP на странице **Расширения** или командой `spirit extension import`; он попадает в их маркетплейс «Личные». См. [Расширения](../customize/extensions.mdx).

Чтобы разместить расширение в маркетплейсе, см. [Публикация через publish](#публикация-через-publish).

## Управление удалённым маркетплейсом расширений

Удалённый маркетплейс расширений — это обслуживаемый каталог с индексом `.spirit/marketplace.json`: Git-репозиторий, статический сайт или локальный каталог. Пользователи добавляют его командой `spirit extension marketplace add <url|path>` или на странице **Расширения** в Desktop, а затем просматривают и устанавливают его записи.

<Tabs items={["Репозиторий-шаблон", "Вручную"]}>
<Tab value="Репозиторий-шаблон">

[Use this template](https://github.com/new?template_owner=SpiritAgents&template_name=extension-template) — создайте собственный репозиторий маркетплейса из `SpiritAgents/extension-template`.

Шаблон содержит структуру реестра, два примера расширений и CI, проверяющий реестр при каждом push и pull request. Чтобы опубликовать расширение:

1. Создайте каркас командой `npm create @spiritagent/extension`.
2. Выполните `npx @spiritagent/extension-toolkit publish ./my-extension /path/to/your-marketplace-clone` — команда скопирует расширение в `extensions/` и объединит запись с `.spirit/marketplace.json`. См. [Публикация через publish](#публикация-через-publish).
3. Отправьте изменения — пользователи добавляют маркетплейс по его Git-URL.

</Tab>
<Tab value="Вручную">

Корень маркетплейса содержит индекс плюс по одному каталогу содержимого на расширение:

```text
my-marketplace/
  .spirit/
    marketplace.json  # индекс
  extensions/
    my-extension/     # каталог содержимого (простой npm-пакет + файлы возможностей)
      icon.svg
      package.json
      ...
```

Относительные пути внутри `marketplace.json` разрешаются относительно корня маркетплейса и не должны содержать сегменты `..` или абсолютные пути.

Поля записи по группам:

- **Идентичность** — `name` (kebab-case; id записи), `version` (semver, без предварительных версий) и `source`: строка пути относительно корня, например `"./extensions/my-extension"`, для локального содержимого или `{ "source": "npm", "package": "@scope/name@1.0.0" }` для фиксации точной версии npm (целостность проверяется по SRI-хешу пакумента при установке).
- **Отображение** — `displayName`, `description`, `icon` (путь к SVG относительно корня), `category`, `keywords`, `homepage`, `author`.
- **Декларация** — `manifest`: декларация времени выполнения, описанная в разделе «`manifest`». Маркетплейс её подтверждает; пакет не может сам заявлять о возможностях.
- **Кураторство** — `featured` и `reviewStatus` (`unverified` / `verified` / `revoked`).

`extension-toolkit publish` может объединить запись за вас — см. [Публикация через publish](#публикация-через-publish).

Проверьте реестр локально — офлайн: схема, имена kebab-case, semver без предварительных версий, формат источников npm, объявленные файлы вкладов для локальных источников и правила для значков:

```bash
npx -y @spiritagent/extension-toolkit marketplace check .
```

Дисциплина проверки: pull request'ы, добавляющие запись или меняющие её `version`, должны сохранять `reviewStatus: "unverified"`; повышение до `verified` происходит отдельным коммитом после человеческой проверки. `.github/workflows/marketplace.yml` репозитория-шаблона — эталонная реализация: он сравнивает индекс с базой PR.

### Локальные маркетплейсы

Любой локальный каталог с `.spirit/marketplace.json` работает как маркетплейс — добавьте его командой `spirit extension marketplace add <path>` или через **Добавить с диска** в Desktop. Локальные маркетплейсы читаются на месте и не требуют CI, что делает их циклом разработки авторов расширений: править, переустановить, повторить.

### Публикация через publish

`extension-toolkit publish` объединяет `.spirit/extension.json` расширения с `.spirit/marketplace.json` целевого маркетплейса и копирует содержимое, необходимое источнику записи:

```bash
npx @spiritagent/extension-toolkit publish ./my-extension ./my-marketplace
```

- Первый аргумент — каталог расширения, второй — корень маркетплейса: любой локальный каталог с `.spirit/marketplace.json`: клон репозитория-шаблона, маркетплейс «Личные» в `{spiritDataDir}/marketplaces/personal` и т. д.
- `--source local` (по умолчанию): копирует весь пакет в `extensions/<name>/` маркетплейса — включая `.spirit/extension.json`, исключая `node_modules` и `.git` — и указывает `source` записи на этот каталог.
- `--source npm`: фиксирует `name@version` из `package.json` расширения как npm-`source` записи; в `extensions/<name>/` копируется только объявленный значок (маркетплейсы хранят значки у себя). Публикация самого npm-пакета по-прежнему выполняется вами через npm CLI.
- `--dry-run`: выводит запись и планируемые действия, ничего не записывая.
- Правила слияния: запись с тем же именем заменяется на месте, иначе добавляется. Новые записи и изменения `version` возвращают `reviewStatus: "unverified"`; повторная публикация той же версии его сохраняет. Поля кураторства вроде `featured` всегда сохраняют значения маркетплейса.
- Сначала выполняется та же проверка, что и в `check`; при ошибке ничего не записывается.
