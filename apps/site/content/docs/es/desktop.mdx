### Shell

El Desktop (solo Electron) tiene una pestaña **Shell** con un PTY integrado. Ese panel es para ti. El agente sigue pasando por [`shell`](./agent/tools.mdx) y aprobación; no escribe en tu PTY.

El CLI no tiene panel PTY integrado. Los comandos siguen ejecutándose mediante la misma herramienta `shell` en el daemon compartido.

Puedes anular el shell PTY del Desktop con `SPIRIT_TERMINAL_SHELL` si necesitas un binario específico.

### Git

La pestaña **Git** muestra cambios e historial. Los chips en el composer pueden iniciar **commit**, **push** o **merge**. Esto es UI del host, no un paquete de Skills.

Esos chips inyectan un prompt fijo. Luego el agente usa las herramientas [workspace y `shell`](./agent/tools.mdx).

### LSP

Activa los servidores de lenguaje en **Settings → Agents**, luego instala un proveedor si falta. Cuando un servidor esté listo, el agente puede llamar a [`get_diagnostics`](./agent/tools.mdx).

| Id              | Lenguajes | Cómo se instala                                           |
| --------------- | --------- | --------------------------------------------------------- |
| `pyright`       | Python    | npm (`pyright`)                                           |
| `gopls`         | Go        | Cadena de herramientas de Go                              |
| `rust-analyzer` | Rust      | rustup                                                    |
| `clangd`        | C, C++    | Paquete de la plataforma (por ejemplo, Homebrew o winget) |
| `jdtls`         | Java      | Manual                                                    |
| `omnisharp`     | C#        | .NET                                                      |

clangd y jdtls no están incluidos. Instálalos tú mismo y luego vuelve a Settings → Agents.

### Tab

Tab es la finalización en línea de Monaco. Acepta el texto fantasma con un Tab. Abre **Settings → Tab**, activa la finalización de código (`codeCompletionEnabled`) y asigna un modelo de chat ligero en **Settings → Models**. Ese espacio también sirve para otras tareas ligeras en segundo plano.

Si la finalización está vacía, verifica que un modelo de chat ligero esté conectado y que la configuración esté activada. Esta no es la conversación del agente.

## Extensiones y automatizaciones

La página Extensiones de la barra lateral lista las extensiones instaladas e importa archivos ZIP. Las automatizaciones tienen su propia vista — [solo Desktop](./customize/automations.mdx).

## Emparejamiento de Web Host

Desktop puede servir un cliente web en la máquina local.

- Escucha predeterminada: `127.0.0.1:7788`
- Configuración → **Redes** → Control remoto web
- La primera visita solicita un **código de emparejamiento de 6 dígitos** desde esa página de configuración
- Cinco intentos fallidos bloquean el emparejamiento hasta que reinicies Web Host
- El token se almacena en el navegador como `spirit-web-host-token`

El agente sigue ejecutándose dentro del daemon compartido. El cliente web recibe una instantánea autenticada; no es un segundo agente.

**Vincular `0.0.0.0` para acceso remoto a LAN no es una ruta de producto abierta.** El daemon y Web Host permanecen en loopback por defecto. Una dirección IPv4 de escucha en LAN en Redes es para una máquina que controlas, no un servidor público.

Anulaciones de desarrollo: `SPIRIT_DESKTOP_WEB_HOST=1`, `SPIRIT_WEB_HOST`, `SPIRIT_WEB_PORT`.
