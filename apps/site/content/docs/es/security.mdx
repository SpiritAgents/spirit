## Llavero

Las claves de API, los secretos de Bedrock / Vertex, los secretos de extensiones y el token de integración de GitHub se almacenan en el llavero del sistema operativo. El nombre del servicio es `{{product.name}}`.

Las claves de proveedor que escribe el asistente de conexión usan el esquema de cuenta `provider::{id}` — una por entrada de proveedor en `config.json` — o `provider::{id}::{slot}` para slots de credenciales compuestas como IAM de Bedrock o una cuenta de servicio de Vertex. Los secretos grandes pueden dividirse en el llavero.

`config.json` contiene entradas de proveedor y referencias de modelos, no los secretos en sí — a menos que optes por una escotilla de escape declarada: un `apiKey` en texto plano (no recomendado), una referencia a variable de entorno `apiKeyEnv`, o una referencia `apiKeyKeyring` / `keyring` por slot a una entrada en un llavero externo. Ver [Config](./config.mdx).

## Aprobaciones

Ver [Aprobaciones](./agent/approvals.mdx). El valor predeterminado es el punto de partida seguro. La omisión aún se detiene para `ask_questions` y el Hook `ask`.

## Daemon local

Desktop y CLI comparten un daemon que se vincula a **`127.0.0.1`** en un puerto aleatorio. Los clientes envían `Authorization: Bearer` usando `{spiritDataDir}/server.token` (modo `0600`).

El acceso remoto `0.0.0.0` **no** es una ruta de producto abierta. No trates un enlace LAN como un agente en la nube alojado.

El emparejamiento de Web Host es un código separado de 6 dígitos en Desktop. Cinco fallos bloquean el código hasta que reinicies Web Host. Ver [Desktop](./desktop.mdx).

## Privacidad

{{product.name|mdx}} no incluye telemetría de desarrollador. Los datos permanecen en el directorio de datos y en el llavero. Ver [PRIVACY.md](https://github.com/SpiritAgents/spirit/blob/main/PRIVACY.md) en el repositorio.

Reporta vulnerabilidades de forma privada (Aviso Privado de GitHub), no en un problema público. Ver [SECURITY.md](https://github.com/SpiritAgents/spirit/blob/main/SECURITY.md).
