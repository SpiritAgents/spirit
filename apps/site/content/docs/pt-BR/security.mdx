## Keyring

Chaves de API, segredos do Bedrock / Vertex, segredos de extensões e o token de integração do GitHub são armazenados no keyring do sistema operacional. O nome do serviço é `{{product.name}}`.

As chaves de provedor gravadas pelo assistente de conexão usam o esquema de conta `provider::{id}` — uma por entrada de provedor no `config.json` — ou `provider::{id}::{slot}` para slots de credenciais compostas, como IAM do Bedrock ou uma conta de serviço do Vertex. Segredos grandes podem ser fragmentados no keyring.

`config.json` contém entradas de provedor e referências de modelo, não os segredos em si — a menos que você opte por uma saída de escape declarada: um `apiKey` em texto simples (não recomendado), uma referência de variável de ambiente `apiKeyEnv`, ou uma referência `apiKeyKeyring` / `keyring` por slot para uma entrada em um keyring externo. Consulte [Configuração](./config.mdx).

## Daemon local

O Desktop e a CLI compartilham um daemon que vincula **`127.0.0.1`** em uma porta aleatória. Os clientes enviam `Authorization: Bearer` usando `{spiritDataDir}/server.token` (modo `0600`).

O acesso remoto `0.0.0.0` **não** é um caminho de produto aberto. Não trate um bind de LAN como um agente de nuvem hospedado.

O pareamento do Web Host é um código separado de 6 dígitos no Desktop. Cinco falhas bloqueiam o código até que você reinicie o Web Host. Consulte [Desktop](./desktop.mdx).

## Privacidade

O {{product.name|mdx}} não envia telemetria de desenvolvedor. Os dados permanecem no diretório de dados e no keyring. Consulte [PRIVACY.md](https://github.com/SpiritAgents/spirit/blob/main/PRIVACY.md) no repositório.

Reporte vulnerabilidades de forma privada (GitHub Private Advisory), não em uma issue pública. Consulte [SECURITY.md](https://github.com/SpiritAgents/spirit/blob/main/SECURITY.md).
