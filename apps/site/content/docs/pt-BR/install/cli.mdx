O CLI é um host de terminal com um TUI e um modo não interativo `-p`. Ele fala com o mesmo daemon local que o [Desktop](./desktop.mdx).

## Script de instalação

macOS e Linux:

```bash
curl -fsSL {{product.websiteOrigin}}/install | bash
```

Windows (PowerShell):

```powershell
irm {{product.websiteOrigin}}/install.ps1 | iex
```

O script baixa um build de `{{product.downloadOrigin|host}}`, verifica o SHA-256 com o `SHA256SUMS.txt` do Release correspondente no GitHub (aborta se não coincidir), descompacta e coloca `spirit` no seu `PATH`.

Abra um novo terminal e então:

```bash
spirit --version
```

## Onde ele fica

Os binários CLI usam SPIRIT_HOME. No Unix, a instalação Stable e os dados compartilhados podem ter o mesmo diretório pai; bin/ e cli/ continuam sendo arquivos de instalação. Essa configuração não seleciona o diretório de dados compartilhados.

|                                                | Padrão                                                                                                                                                                                                                | Substituição      |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| Binários do CLI                                | Unix: `~/.spirit` · Windows: `%LOCALAPPDATA%\Spirit`                                                                                                                                                                  | `SPIRIT_HOME`     |
| Sessões, configuração, apontadores de chaveiro | Stable: `~/{{product.stable.userDataFolderName}}` · Dev: `~/{{product.dev.userDataFolderName}}` · Windows: `%USERPROFILE%\{{product.stable.userDataFolderName}}` / `%USERPROFILE%\{{product.dev.userDataFolderName}}` | `SPIRIT_DATA_DIR` |

No Unix, o script cria um link `$SPIRIT_HOME/bin/spirit` → `$SPIRIT_HOME/cli/current/bin/spirit` e adiciona `export PATH="$SPIRIT_HOME/bin:$PATH"` ao final de `~/.profile`, `~/.bashrc` e `~/.zshrc` (marcador `# spirit cli`).

## Fixar uma versão ou espelho

| Variável               | Padrão                                 | Função                                      |
| ---------------------- | -------------------------------------- | ------------------------------------------- | ----------- |
| `SPIRIT_HOME`          | `~/.spirit` ou `%LOCALAPPDATA%\Spirit` | Diretório de instalação dos binários do CLI |
| `SPIRIT_VERSION`       | `latest`                               | Segmento de versão na URL de download       |
| `SPIRIT_DOWNLOAD_HOST` | `{{product.downloadOrigin|host}}`                                     | Host de CDN |

```bash
SPIRIT_VERSION=0.1.0 curl -fsSL {{product.websiteOrigin}}/install | bash
```

Você também pode baixar um arquivo do CLI da [página de download](/pt-BR/download) ou do [GitHub Releases](https://github.com/SpiritAgents/spirit/releases/latest) e descompactar você mesmo.

## Primeira execução

```bash
cd /path/to/your/project
spirit
```

Isso abre o TUI. Adicione um provedor com `/model add`, ou do shell com `spirit model add`. Veja o [quickstart](../quickstart.mdx).
