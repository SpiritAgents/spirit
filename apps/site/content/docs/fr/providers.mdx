title: Fournisseurs
description: Apportez votre propre clé, exécutez l'assistant de connexion et conservez le même flux de travail d'agent lorsque vous changez de maison.
---

Spirit est BYOK. Vous créez une clé dans la console d'un fournisseur, vous la collez dans Desktop ou la CLI, et Spirit la stocke dans le trousseau du système d'exploitation. Changer de maison ne modifie pas la façon dont vous ouvrez un espace de travail, approuvez des modifications ou exécutez l'agent.

L'assistant de connexion se trouve dans **Paramètres → Modèles** sur Desktop, ou `/model add` / `spirit model add` dans la CLI. Des champs supplémentaires n'apparaissent que lorsque ce fournisseur en a besoin.

Spirit communique avec les fournisseurs via l'un des quatre transports. L'assistant fixe le type ou vous permet de choisir.

| Transport           | Libellé de l'assistant             | Utilisation typique                                                                 |
| ------------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| `openai-compatible` | API Chat Completions               | La plupart des points de terminaison compatibles OpenAI                             |
| `open-responses`    | API Responses / API Open Responses | OpenAI, Azure, Vercel AI Gateway, Hugging Face et chemins de passerelle facultatifs |
| `anthropic`         | API Messages                       | Anthropic, MiniMax et points de terminaison compatibles Messages facultatifs        |
| `bedrock`           | Amazon Bedrock                     | Uniquement pour Amazon Bedrock                                                      |

Google Gemini et Vertex AI utilisent toujours Chat Completions. Si un profil demande Responses ou Messages, Spirit revient à `openai-compatible`.

Certaines maisons ajoutent une seconde dimension au-dessus de la clé :

- **Sites régionaux** — Moonshot AI, SiliconFlow, MiniMax (Chine / International) ; Alibaba (région + `workspaceId`) ; Tencent TokenHub (Guangzhou / Singapour)
- **Points de terminaison de plan** — Alibaba Token Plan, StepFun Step Plan, Z.ai / Zhipu AI GLM Coding Plan
- **Champs cloud** — région Bedrock, nom de ressource Azure, compte Cloudflare (et passerelle facultative), projet / emplacement Vertex

Si un fournisseur n'a aucune de ces options, l'assistant est simplement : clé → importer les modèles → choisir un modèle de chat actif.

Spirit importe le catalogue de modèles et vous permet d'attribuer le modèle de chat actif, ainsi que les emplacements d'image / vidéo / chat léger lorsque le catalogue marque ces capacités. Le raisonnement et la recherche Web intégrée suivent le modèle et le transport, et non un bouton Spirit séparé.

## Catalogue

Voici les maisons dans le sélecteur de connexion, dans le même ordre. Chaque section contient la clé, le transport et les champs supplémentaires de cette maison. L'assistant Desktop et CLI ci-dessus est le même pour chaque maison.

### OpenAI

Créez une clé API dans la [plateforme OpenAI](https://platform.openai.com/api-keys). Spirit ne vend pas l'utilisation d'OpenAI.

L'assistant fixe **API Responses** (`open-responses`). Il n'y a pas de sélecteur de transport. Base par défaut : `https://api.openai.com/v1`.

Chat après import. Le raisonnement suit le modèle. La génération d'images et de vidéos n'apparaît que lorsque le catalogue marque ces capacités — attribuez-les dans les emplacements de modèles d'image / vidéo.

### Anthropic

Créez une clé API dans la [console Anthropic](https://console.anthropic.com/settings/keys).

**API Messages** fixée (`anthropic`). Base par défaut : `https://api.anthropic.com/v1`.

Chat après import. Le raisonnement suit le modèle. Aucun emplacement de génération d'image ou de vidéo côté Spirit, sauf si une entrée de catalogue ultérieure le marque.

### Google

Créez une clé API dans [Google AI Studio](https://aistudio.google.com/apikey).

**API Chat Completions** fixée (`openai-compatible`). Demander Responses ou Messages revient à Chat Completions. Base par défaut : `https://generativelanguage.googleapis.com/v1beta`.

Chat après import. La génération d'images est attribuée uniquement lorsque le catalogue la marque. Pour Vertex AI (projet / emplacement GCP), utilisez [Google Vertex AI](#google-vertex-ai).

### SpaceXAI

### Vercel AI Gateway

Créez une clé dans le tableau de bord [Vercel AI Gateway](https://vercel.com/docs/ai-gateway).

**API Open Responses** fixe (`open-responses`). Base par défaut : `https://ai-gateway.vercel.sh/v1`.

Discussion plus ce que le catalogue de la passerelle expose. La génération d'images est tirée du catalogue `type=image`, pas des tags.

N'inférez pas la vision ou la génération d'images à partir des tags. MiniMax M3 via cette passerelle ne renvoie pas de flux de raisonnement affichable sur Open Responses.

### Cloudflare AI Gateway

Créez un jeton API dans le [tableau de bord Cloudflare](https://developers.cloudflare.com/ai-gateway/). Vous avez également besoin de l'ID de compte.

Sélecteur : **Chat Completions**, **Open Responses** ou **Messages**. La base est construite à partir du compte : `https://api.cloudflare.com/client/v4/accounts/{accountId}/ai/v1`.

- **ID de compte** (requis) — hexadécimal de 32 caractères
- **ID de passerelle** (facultatif)

Sans ID de compte, l'assistant ne peut pas construire la base API. La discussion et les autres capacités suivent les modèles que la passerelle expose.

### Azure

Créez une clé pour votre ressource Azure OpenAI dans le [portail Azure](https://portal.azure.com).

Corrigé **API Responses** (`open-responses`). Pas de sélecteur de transport.

- **Nom de ressource** (obligatoire) — 2 à 64 caractères, lettres, chiffres et traits d'union ; ne peut pas commencer ni se terminer par un trait d'union

Spirit construit `https://{resource}.openai.azure.com/openai/v1`. Chat après importation. La génération d'images suit le catalogue Azure lorsqu'il est marqué.

### Amazon Bedrock

Dans la [console AWS Bedrock](https://console.aws.amazon.com/bedrock), créez une clé API Bearer ou un utilisateur IAM pouvant appeler Bedrock.

Corrigé **Amazon Bedrock** (`bedrock`). Format d'hôte par défaut : `https://bedrock.us-east-1.amazonaws.com`.

- **Région AWS** (obligatoire), par exemple `us-east-1`
- **Authentification** : **Bearer** ou **IAM**
  - Bearer — collez une clé API Bedrock et un identifiant de modèle. Les modèles ne sont **pas** récupérés automatiquement.
  - IAM — ID de clé d'accès + clé d'accès secrète. Spirit répertorie les modèles de base du compte.

Chat après avoir choisi un modèle. Les autres capacités suivent ce modèle. Les clés Bearer ne fonctionnent que pour l'inférence. `ListFoundationModels` n'accepte pas Bearer, donc l'importation du catalogue nécessite IAM.

### Google Vertex AI

Utilisez un projet GCP avec Vertex AI activé. L'authentification se fait par ADC, un compte de service ou une clé API Express — pas une clé OpenAI générique.

Corrigé **API Chat Completions**. Les requêtes Responses ou Messages reviennent à Chat Completions. La base devient `https://{location}-aiplatform.googleapis.com/v1/projects/{project}/locations/{location}`.

- **ID du projet GCP** et **Emplacement** (obligatoires), par exemple `us-central1`
- **Authentification**
  - **ADC** — Informations d'identification par défaut de l'application sur cette machine (`GOOGLE_APPLICATION_CREDENTIALS`)
  - **Compte de service** — e-mail du client + clé privée ; utilisé pour récupérer la liste des modèles
  - **Clé API Express** — ne peut pas récupérer le catalogue ; ajoutez un identifiant de modèle manuellement

Chat après la sélection d'un modèle. Pour les clés AI Studio sans projet GCP, utilisez [Google](#google). Le mode Express ne peut pas importer la liste des modèles. Le mode compte de service nécessite à la fois l'e-mail et la clé privée pour lister les modèles.

### Personnalisé

Utilisez la clé API attendue par votre point de terminaison. Il n'y a pas de fournisseur personnalisé hébergé par Spirit.

Sélecteur : **Chat Completions**, **Open Responses** ou **Messages**. Vous devez fournir l'**URL de base**. La valeur par défaut indicative est `https://api.openai.com/v1` si vous la laissez vide.

Saisissez la racine documentée par le fournisseur, y compris le suffixe de version lorsqu'il l'exige (`/v1`, `/v1/openai`, …). Spirit ne devine pas le chemin pour les points de terminaison personnalisés.

Vous pouvez également définir un nom d'affichage pour le groupe de fournisseurs afin que plusieurs points de terminaison personnalisés restent distinguables.

Après la connexion, importez ou saisissez les identifiants de modèles. Marquez les capacités chat / image / vidéo dans l'assistant lorsque le point de terminaison ne publie pas de catalogue que Spirit comprend.
