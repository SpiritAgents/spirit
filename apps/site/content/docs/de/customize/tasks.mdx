<Callout type="info">Nur Desktop.</Callout>

Tasks führen vordefinierte Arbeitsbereichsbefehle aus der Befehlspalette von {{product.name|mdx}} Desktop aus: Öffnen Sie die Palette (`Mod+Shift+P`), wählen Sie **Arbeitsbereich → Task ausführen** und dann einen Task aus der Liste auf der zweiten Ebene. Der Task läuft in einem Terminal-Tab im rechten Werkzeugbereich. Die Gruppe **Arbeitsbereich** erscheint in der Palette nur, wenn mindestens ein gültiger Task existiert.

{{product.name|mdx}} Tasks ist ein eigenes System, nicht VS Code Tasks. Es liest ein striktes JSON-Format von {{product.name|mdx}} und — als Kompatibilitätsimport — VS Codes `tasks.json`, mit einer klar definierten Teilmenge der VS-Code-Felder. Ein Task, der nicht exakt wie konfiguriert laufen kann, wird vollständig ausgeblendet, statt halb konfiguriert zu laufen; siehe [Warum ein Task ausgeblendet wird](#warum-ein-task-ausgeblendet-wird).

## Task-Dateien

Drei Quellen werden gelesen, höchste Priorität zuerst:

| Priorität | Quelle                                                       | Erforderliche Markierung | Hinweise                                        |
| --------- | ------------------------------------------------------------ | ------------------------ | ----------------------------------------------- |
| 1         | `<workspace>/{{product.workspaceDataFolderName}}/tasks.json` | `"schemaVersion": 1`     | Spirits eigenes Format                          |
| 2         | `<data dir>/tasks.json`                                      | `"schemaVersion": 1`     | Benutzerebene, gilt für jeden Arbeitsbereich    |
| 3         | `<workspace>/.vscode/tasks.json`                             | `"version": "2.0.0"`     | VS-Code-Kompatibilitätsimport, schreibgeschützt |

Nur das Stammverzeichnis des Arbeitsbereichs wird durchsucht — verschachtelte Verzeichnisse nicht. `<data dir>` ist das {{product.name|mdx}}-Datenverzeichnis (zum Beispiel `~/{{product.stable.userDataFolderName}}` unter macOS). Eine Datei, die fehlt, unlesbar ist, ungültiges JSON enthält oder die falsche Markierung trägt, liefert keine Tasks.

Die drei Dateien werden live überwacht; die Palettenliste aktualisiert sich automatisch, wenn sich eine davon ändert.

Alle drei Quellen verschmelzen in einem Namespace. Definieren mehrere Quellen dasselbe `label`, gewinnt die Quelle mit der höchsten Priorität — sowohl für die Palettenliste als auch für `dependsOn`-Verweise.

`.vscode/tasks.json` wird tolerant geparst, weil Dateien in der Praxis JSONC sind: `//`- und `/* */`-Kommentare sowie abschließende Kommas werden akzeptiert. Spirits eigene Dateien sind striktes JSON — ein Kommentar macht die Datei ungültig.

## Workspace-Vertrauen

Workspace-Aufgabendateien kommen mit dem Repository und sind daher nicht vertrauenswürdige Daten: `{{product.workspaceDataFolderName}}/tasks.json` und `.vscode/tasks.json` werden erst geladen, nachdem Sie den Workspace-Inhalt genehmigt haben. Die benutzerbezogene `tasks.json` ({{product.name|mdx}}-Datenverzeichnis) ist implizit vertrauenswürdig und wird immer geladen.

Wenn {{product.name|mdx}} Desktop Workspace-Aufgabendateien (oder eine Änderung daran) erkennt, fragt es einmal: Der Dialog listet die verfügbar werdenden Tasks mit ihren Befehlen; ein Klick auf einen Eintrag öffnet die Quelldatei. Benötigen auch Workspace-Hooks eine Zustimmung, erscheinen beide Listen in einem gemeinsamen Dialog.

- **Einmal zulassen** — die Tasks werden nur für diese Sitzung geladen.
- **Immer vertrauen** — für genau diesen Dateiinhalt gemerkt.
- **Ablehnen** — die Workspace-Tasks bleiben nicht verfügbar; die Ablehnung wird für genau diesen Inhalt in dieser Sitzung gemerkt.

Das Bearbeiten einer der Dateien fragt erneut (die Zustimmung ist an den Inhaltshash gebunden). Zur Wiederherstellung nach einer Ablehnung: Datei bearbeiten (erneute Frage) oder App neu starten.

Diese Sperre ist die strukturelle Voraussetzung für automatische Auslöser: `runOn: "folderOpen"` läuft erst nach Genehmigung, und `worktreeCreated` bleibt deaktiviert.

## Felder

Verhalten pro Feld, ausgewertet nach dem Zusammenführen: Standardwerte auf Dateiebene < OS-Block auf Dateiebene < Task < OS-Block auf Taskebene.

### Kernfelder

| Feld                                     | Verhalten    | Hinweise                                                                                                                                                                                                                                                           |
| ---------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| `label`                                  | Erforderlich | Einträge ohne nicht-leeres Label werden vollständig verworfen — sie erreichen weder das Menü noch den Abhängigkeitsgraphen                                                                                                                                         |
| `type`                                   | Unterstützt  | `shell` (Standard) oder `process`. Jeder andere String (`npm`, `grunt`, …) ist ein erweiterungsangepasster Eintrag und wird vollständig ignoriert: nicht ausgeblendet, nicht gelistet, Geschwister unbetroffen                                                     |
| `command`                                | Unterstützt  | `string`, `string[]` oder `{ value, quoting }`. Ein Task, dessen zusammengeführtes Kommando fehlt, wird ausgeblendet — auch bei `shell`-Tasks (strenger als VS Code)                                                                                               |
| `args`                                   | Unterstützt  | Array aus `string` oder `{ value, quoting }`                                                                                                                                                                                                                       |
| `quoting`                                | Unterstützt  | `escape`, `strong` (Standard) oder `weak`; ungültige Werte fallen auf `strong` zurück. Gilt für `args` und die Objektform `{ value, quoting }`; ein `command` als einfacher String wird wörtlich an die Shell übergeben und darf daher rohe Shell-Syntax enthalten |
| `options.cwd`                            | Unterstützt  | Arbeitsverzeichnis des Prozesses                                                                                                                                                                                                                                   |
| `options.env`                            | Unterstützt  | Zusätzliche Umgebungsvariablen, über der Host-Umgebung zusammengeführt                                                                                                                                                                                             |
| `options.shell`                          | Unterstützt  | `{ executable, args }` — Shell, die für `shell`-Tasks statt der Standard-Terminal-Shell verwendet wird                                                                                                                                                             |
| `windows` / `osx` / `linux` (Taskebene)  | Unterstützt  | `{ command, args, options }`-Überschreibungen für das aktuelle OS.                                                                                                                                                                                                 |
| `windows` / `osx` / `linux` (Dateiebene) | Unterstützt  | Gleiche Form, wirkt als OS-spezifische Standardebene für jeden Task in der Datei                                                                                                                                                                                   |
| Standardwerte auf Dateiebene             | Unterstützt  | Nur `command`, `args`, `options`, `type`, `isBackground`, `promptOnClose`, `presentation` dürfen als Standardwerte auf Dateiebene wirken.                                                                                                                          |
| `isBackground`                           | Unterstützt  | Das Beenden gilt als Benutzerabbruch, nie als Fehlschlag. Ein davon abhängiger Task wird ausgeblendet (siehe unten)                                                                                                                                                |
| `promptOnClose`                          | Unterstützt  | Das Schließen des Tabs bei laufendem Prozess fragt nach einer Bestätigung                                                                                                                                                                                          |
| `dependsOn`                              | Unterstützt  | Ein Label-String oder ein Array von Label-Strings. Die Objektform (`{ "type": … }`, `{ "task": … }`) blendet den Task aus                                                                                                                                          |
| `dependsOrder`                           | Unterstützt  | `parallel` (Standard) oder `sequence`                                                                                                                                                                                                                              |
| `detail`                                 | Unterstützt  | Wird neben dem Label in der Palettenliste angezeigt                                                                                                                                                                                                                |
| `icon.id`                                | Unterstützt  | Menüsymbol: zuerst {{product.name|mdx}} Icons, dann Lucide, mit einem Terminalsymbol als Fallback |
| `icon.color`                             | Ignoriert    | Rein darstellerisch                                                                                                                                                                                                                                                |
| `hide`                                   | Unterstützt  | Aus der Palettenliste ausgeblendet, aber weiterhin auflösbar — der Task kann als `dependsOn`-Abhängigkeit laufen                                                                                                                                                   |

### Ausführungsoptionen

| Feld                           | Verhalten     | Hinweise                                                                                                   |
| ------------------------------ | ------------- | ---------------------------------------------------------------------------------------------------------- |
| `runOptions.reevaluateOnRerun` | Unterstützt   | Standard `true`. `false` legt die erste Auflösung für spätere erneute Ausführungen im Cache ab             |
| `runOptions.runOn`             | Eingeschränkt | `default` und `folderOpen` werden unterstützt; `worktreeCreated` blendet den Task aus                      |
| `runOptions.instanceLimit`     | Unterstützt   | Standard `1`. Das Überschreiten des Limits öffnet einen Dialog (siehe [Tasks ausführen](#tasks-ausführen)) |
| `runOptions.instancePolicy`    | Eingeschränkt | Nur `prompt` wird unterstützt. `terminateNewest`, `terminateOldest`, `warn`, `silent` blenden den Task aus |

### Darstellung

| Feld                                | Verhalten   | Hinweise                                                                                   |
| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------ |
| `presentation.echo`                 | Unterstützt | Schreibt die Kommandozeile vor der Prozessausgabe in das Terminal                          |
| `presentation.reveal`               | Unterstützt | `always` (Standard), `silent` oder `never` — siehe [Tasks ausführen](#tasks-ausführen)     |
| `presentation.focus`                | Unterstützt | Impliziert reveal und verschiebt den Tastaturfokus in das Terminal                         |
| `presentation.panel`                | Unterstützt | `shared` (Standard), `dedicated` oder `new` — Richtlinie für die Terminal-Wiederverwendung |
| `presentation.clear`                | Unterstützt | Leert das Terminal vor einer Wiederholung, die es wiederverwendet                          |
| `presentation.close`                | Unterstützt | Schließt den Tab automatisch, wenn der Prozess endet                                       |
| `presentation.preserveTerminalName` | Unterstützt | Behält das Task-Label als Tab-Titel statt des Prozesstitels                                |
| `presentation.showReuseMessage`     | Ignoriert   | Rein darstellerisch                                                                        |
| `presentation.group`                | Ignoriert   | Terminal-Gruppierung ist nicht Teil des Umfangs                                            |

### Ignorierte Felder

Diese Felder zu tragen blendet einen Task nie aus: `problemMatcher` (jede Form, auf jeder Ebene), `presentation.revealProblems`, `group` (Build-/Test-Gruppierung), `icon.color`, `presentation.showReuseMessage`, `presentation.group`, `inAgents`. Das `inputs`-Array auf Dateiebene wird schlicht nicht gelesen — aber ein `${input:*}`-_Verweis_ innerhalb eines Tasks blendet diesen Task aus (siehe [Variablen](#variablen)).

## Variablen

Unterstützte Verweise, ersetzt, wenn der Task aufgelöst wird:

| Variable                     | Wert                                                |
| ---------------------------- | --------------------------------------------------- | ------------------------------------------------- |
| `${workspaceFolder}`         | Stammpfad des Arbeitsbereichs                       |
| `${workspaceFolderBasename}` | Ordnername des Arbeitsbereichs-Stammverzeichnisses  |
| `${cwd}`                     | {{product.name|mdx}} Desktops eigenes Prozess-Arbeitsverzeichnis |
| `${userHome}`                | Home-Verzeichnis des OS-Benutzers                   |
| `${pathSeparator}`, `${/}`   | Der OS-Pfadtrenner                                  |
| `${env:NAME}`                | Umgebungsvariable `NAME` (leer, wenn nicht gesetzt) |

Die Prüfung deckt `command`, `args`, `options.cwd`, `options.env`-Werte und `options.shell` ab. Jeder andere `${…}`-Verweis — `${file}`, `${selectedText}`, `${lineNumber}`, `${config:*}`, `${command:*}`, `${input:*}`, `${defaultBuildTask}`, … — blendet den Task aus. Wenn kein Arbeitsbereich geöffnet ist, werden Tasks, die `${workspaceFolder}` oder `${workspaceFolderBasename}` referenzieren, für diesen Auflösungsdurchlauf ausgeblendet.

## Warum ein Task ausgeblendet wird

Ein Task, der nicht exakt wie konfiguriert laufen kann, wird vollständig ausgeblendet, statt halb konfiguriert zu laufen. Der Task verschwindet aus der Palette; der Grund wird mit einer stabilen Regel-ID aufgezeichnet.

| Regel                        | Begründung                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `unsupportedVariable`        | Das Einsetzen eines geratenen Werts würde ein anderes Kommando ausführen als konfiguriert                     |
| `dependsOnObjectForm`        | Erweiterungstypisierte Abhängigkeitseinträge sind nicht ausführbar                                            |
| `dependsOnBackground`        | Ein Hintergrundtask endet nie, sodass die Kette nichts Wohldefiniertes hat, auf das sie warten kann           |
| `instancePolicy`             | Es existiert nur die interaktive Nachfrage; stille Richtlinien würden Instanzen ungesehen beenden             |
| `cyclicDependency`           | Ein Abhängigkeitszyklus könnte nie starten                                                                    |
| `transitiveHiddenDependency` | Hängt von einem Label ab, das selbst ausgeblendet ist oder nicht existiert — das Ausblenden pflanzt sich fort |
| `invalidTask`                | Kein Label (wird vollständig verworfen) oder kein `command` irgendwo in der Zusammenführungskette             |

Um einen verschwundenen Task zu diagnostizieren, starten Sie Desktop mit aktiviertem Debug-Kanal — jeder ausgeblendete Task wird mit seiner Regel-ID protokolliert:

```bash
SPIRIT_DESKTOP_TASKS_DEBUG=1
```

Die Logzeile hat die Form `[desktop-host][tasks] hidden <file>#<label> rule=<id>`.

## Tasks ausführen

Tasks starten durch einen expliziten Klick in der Palette; nur in vertrauenswürdigen Workspaces laufen Tasks mit `runOn: "folderOpen"` zusätzlich automatisch beim Öffnen des Ordners. Beim Speichern einer Datei oder bei einem anderen Ereignis läuft nie etwas. `worktreeCreated` wird weiterhin nicht unterstützt.

- **Abhängigkeiten** — `dependsOn`-Labels werden im zusammengeführten Namespace aufgelöst. Mit `dependsOrder: "parallel"` (Standard) starten alle Abhängigkeiten gemeinsam, jede in ihrem eigenen Terminal mit eigener Darstellung, und der Haupttask startet erst, nachdem jede Abhängigkeit beendet wurde; endet eine Abhängigkeit mit einem Exit-Code ungleich null, läuft der Haupttask nicht — dieselbe Fehlersemantik wie VS Code. Mit `"sequence"` laufen die Abhängigkeiten einzeln der Reihe nach, und der erste Exit-Code ungleich null bricht die Kette ab, bevor der Haupttask startet. Eine bereits laufende Abhängigkeit wird abgewartet, nicht neu gestartet.
- **Instanzlimit** — `runOptions.instanceLimit` ist standardmäßig `1`. Das Starten einer weiteren Instanz über das Limit hinaus listet die laufenden Instanzen mit ihrer Laufzeit auf; wähle eine aus (die erste ist vorausgewählt) und wähle **Ersetzen**, um sie zu beenden und den neuen Lauf zu starten, oder **Abbrechen**. Es gibt keine Option, das konfigurierte Limit zu überschreiten.
- **Ordneröffnungs-Auslöser** — `runOn: "folderOpen"` führt den Task bei der Aktivierung des Workspaces automatisch aus, aber nur in vertrauenswürdigen Workspaces (nach Genehmigung oder mit vorhandenem Vertrauenseintrag); ein abgelehnter Workspace führt ihn nie aus. Nach dem Genehmigen der Vertrauensfrage laufen die Ordneröffnungs-Tasks dieser Sitzung sofort. Der Auslöser feuert höchstens einmal pro Aktivierungsrunde — das Bearbeiten der `tasks.json` führt nie etwas erneut aus — und läuft der Task bereits am Instanzlimit, wird der automatische Lauf still übersprungen (kein Dialog).
- **Terminal-Wiederverwendung** — nur Terminals beendeter Tasks werden je wiederverwendet. `panel: "shared"` und `panel: "dedicated"` verwenden beide das eigene freie Terminal dieses Tasks wieder, wenn eines existiert (der Pool gilt pro Task), und öffnen sonst einen neuen Tab; `panel: "new"` öffnet immer einen frischen Tab.
- **Echo** — mit `presentation.echo` (standardmäßig an) wird die Kommandozeile vor der Prozessausgabe in das Terminal geschrieben.
- **Reveal** — `always` (Standard) klappt den Werkzeugbereich beim Start aus; `silent` hält ihn beim Start geschlossen und klappt ihn nur aus, wenn der Task mit einem Exit-Code ungleich null endet; `never` klappt nie automatisch aus. `focus: true` impliziert reveal und verschiebt zusätzlich den Tastaturfokus in das Terminal. Zwei Abweichungen gegenüber VS Code: `reveal: "silent"` klappt nur bei einem Exit-Code ungleich null aus ({{product.name|mdx}} hat keinen problemMatcher-Auslösepfad), und `presentation.revealProblems` hat überhaupt keine Wirkung — es unterdrückt weder eine Terminal-Anzeige noch löst es eine aus.
- **Clear** — `presentation.clear` leert das Terminal vor einer Wiederholung, die es wiederverwendet.
- **Close** — `presentation.close` schließt den Tab beim Beenden automatisch, unabhängig vom Exit-Code.
- **Terminalname beibehalten** — `presentation.preserveTerminalName` behält das Task-Label als Tab-Titel; sonst ersetzt der Titel des laufenden Prozesses ihn.
- **Hintergrund** — `isBackground: true` markiert den Task als nie endend; sein Beenden gilt als Benutzerabbruch, nie als Fehlschlag (kein Fehler-Reveal).
- **Schließbestätigung** — `promptOnClose: true` fragt nach einer Bestätigung, wenn Sie einen Tab schließen, dessen Prozess noch läuft; das Bestätigen beendet den Prozess.
- **Ausgeblendete Tasks** — Tasks mit `hide: true` erscheinen nie in der Palette, können aber weiterhin als `dependsOn`-Abhängigkeiten laufen.

## Beispiel

Eine vollständige `{{product.workspaceDataFolderName}}/tasks.json` — eine Build- → Test- → Paket-Sequenzkette plus ein Hintergrund-Watch-Task:

```json
{
  "schemaVersion": 1,
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "pnpm",
      "args": ["run", "build"],
      "detail": "Production build",
      "icon": { "id": "hammer" }
    },
    {
      "label": "test",
      "command": "pnpm",
      "args": ["run", "test"],
      "dependsOn": ["build"],
      "dependsOrder": "sequence"
    },
    {
      "label": "package",
      "command": "bash",
      "args": ["${workspaceFolder}/scripts/package.sh"],
      "options": {
        "cwd": "${workspaceFolder}",
        "env": { "CHANNEL": "stable" }
      },
      "dependsOn": ["test"],
      "dependsOrder": "sequence",
      "presentation": { "clear": true, "panel": "shared" }
    },
    {
      "label": "watch",
      "command": "pnpm",
      "args": ["run", "watch"],
      "isBackground": true,
      "presentation": { "reveal": "silent", "panel": "dedicated" }
    }
  ]
}
```

- `test` läuft erst, nachdem `build` mit null endet; `package` läuft dann nach `test` und verwendet dasselbe, zuvor geleerte Terminal wieder.
- `package` löst `${workspaceFolder}` zur Laufzeit auf und fügt `CHANNEL` zur Prozessumgebung hinzu.
- `watch` bleibt unauffällig (`silent` zeigt nur bei einem Exit-Code ungleich null) und sein Beenden gilt nie als Fehlschlag. Beachten Sie, dass nichts davon abhängen darf — ein `dependsOn`-Eintrag, der auf einen Hintergrundtask zeigt, wird ausgeblendet.
