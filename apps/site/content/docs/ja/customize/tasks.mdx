<Callout type="info">デスクトップのみ。</Callout>

タスクは、定義済みのワークスペースコマンドを Spirit Desktop のコマンドパレットから実行します: パレットを開き（`Mod+Shift+P`）、**ワークスペース → タスクの実行** を選んで、2 段目のリストからタスクを選択します。タスクは右側のツールパネル内のターミナルタブで実行されます。**ワークスペース** グループは、有効なタスクが 1 つ以上存在する場合にのみパレットに表示されます。

Spirit タスクは独自のシステムであり、VS Code タスクではありません。厳密な JSON の Spirit フォーマットを読み取り、互換性インポートとして VS Code の `tasks.json` も読み取ります（VS Code のフィールドのうち、明確に定義されたサブセットを使用）。設定どおりに正確に実行できないタスクは、不完全な設定のまま実行されるのではなく、完全に非表示になります。[タスクが非表示になる理由](#タスクが非表示になる理由) を参照してください。

## タスクファイル

3 つのソースが読み取られます（優先度の高い順）:

| 優先度 | ソース                           | 必須マーカー         | 備考                                         |
| ------ | -------------------------------- | -------------------- | -------------------------------------------- |
| 1      | `<workspace>/.spirit/tasks.json` | `"schemaVersion": 1` | Spirit 独自のフォーマット                    |
| 2      | `<data dir>/tasks.json`          | `"schemaVersion": 1` | ユーザーレベル。すべてのワークスペースに適用 |
| 3      | `<workspace>/.vscode/tasks.json` | `"version": "2.0.0"` | VS Code 互換インポート。読み取り専用         |

スキャンされるのはワークスペースのルートのみで、ネストされたディレクトリは対象外です。`<data dir>` は Spirit のデータディレクトリです（macOS では例えば `~/Library/Application Support/Spirit`）。ファイルが存在しない、読み取れない、無効な JSON である、または誤ったマーカーを持つ場合、そのファイルからはタスクは取り込まれません。

3 つのファイルはライブで監視され、いずれかが変更されるとパレットのリストが自動的に更新されます。

3 つのソースはすべて 1 つの名前空間にマージされます。複数のソースが同じ `label` を定義している場合、パレットのリストと `dependsOn` 参照の両方で、最も優先度の高いソースが優先されます。

`.vscode/tasks.json` は、実際のファイルが JSONC であるため寛容にパースされます: `//` と `/* */` のコメントや末尾のカンマが許容されます。Spirit 独自のファイルは厳密な JSON で、コメントがあるとファイルは無効になります。

## フィールド

フィールドごとの動作です。マージ後に次の順序で評価されます: ファイルレベルのデフォルト < ファイルレベルの OS ブロック < タスク < タスクレベルの OS ブロック。

### コアフィールド

| フィールド                                    | 動作 | 備考                                                                                                                                                                                                                                            |
| --------------------------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`                                       | 必須 | 空でないラベルを持たない項目は完全に除外され、メニューや依存グラフに到達しません                                                                                                                                                                |
| `type`                                        | 対応 | `shell`（デフォルト）または `process`。その他の文字列（`npm`、`grunt`、…）は拡張機能でカスタマイズされたエントリであり、完全に無視されます: 非表示ではなく、リストにも出ず、兄弟タスクにも影響しません                                          |
| `command`                                     | 対応 | `string`、`string[]`、または `{ value, quoting }`。マージ後のコマンドが欠けているタスクは非表示になります — `shell` タスクでも同様です（VS Code より厳格）                                                                                      |
| `args`                                        | 対応 | `string` または `{ value, quoting }` の配列                                                                                                                                                                                                     |
| `quoting`                                     | 対応 | `escape`、`strong`（デフォルト）、または `weak`。無効な値は `strong` にフォールバックします。`args` とオブジェクト形式 `{ value, quoting }` に適用されます。文字列形式の `command` はそのままシェルに渡されるため、生のシェル構文を含められます |
| `options.cwd`                                 | 対応 | プロセスの作業ディレクトリ                                                                                                                                                                                                                      |
| `options.env`                                 | 対応 | ホスト環境の上にマージされる追加の環境変数                                                                                                                                                                                                      |
| `options.shell`                               | 対応 | `{ executable, args }` — `shell` タスクでデフォルトのターミナルシェルの代わりに使うシェル                                                                                                                                                       |
| `windows` / `osx` / `linux`（タスクレベル）   | 対応 | 現在の OS に対する `{ command, args, options }` の上書き。                                                                                                                                                                                      |
| `windows` / `osx` / `linux`（ファイルレベル） | 対応 | 同じ形状で、ファイル内のすべてのタスクに対する OS 固有のデフォルトレイヤーとして機能します                                                                                                                                                      |
| ファイルレベルのデフォルト                    | 対応 | ファイルレベルのデフォルトとして機能できるのは `command`、`args`、`options`、`type`、`isBackground`、`promptOnClose`、`presentation` のみです。                                                                                                 |
| `isBackground`                                | 対応 | 終了はユーザーによる終了としてカウントされ、失敗としてはカウントされません。これに依存する別のタスクは非表示になります（後述）                                                                                                                  |
| `promptOnClose`                               | 対応 | プロセスが生きている間にタブを閉じると確認を求めます                                                                                                                                                                                            |
| `dependsOn`                                   | 対応 | ラベル文字列、またはラベル文字列の配列。オブジェクト形式（`{ "type": … }`、`{ "task": … }`）はタスクを非表示にします                                                                                                                            |
| `dependsOrder`                                | 対応 | `parallel`（デフォルト）または `sequence`                                                                                                                                                                                                       |
| `detail`                                      | 対応 | パレットのリストでラベルの横に表示されます                                                                                                                                                                                                      |
| `icon.id`                                     | 対応 | メニューアイコン: まず Spirit Icons、次に Lucide、フォールバックとしてターミナルのグリフ                                                                                                                                                        |
| `icon.color`                                  | 無視 | 純粋に見た目だけの指定です                                                                                                                                                                                                                      |
| `hide`                                        | 対応 | パレットのリストからは隠れますが、解決は可能です — タスクは `dependsOn` の依存として実行できます                                                                                                                                                |

### 実行オプション

| フィールド                     | 動作     | 備考                                                                                                                   |
| ------------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `runOptions.reevaluateOnRerun` | 対応     | デフォルトは `true`。`false` は最初の解決結果を後の再実行用にキャッシュします                                          |
| `runOptions.runOn`             | 制限付き | `default` のみサポート。`folderOpen` / `worktreeCreated` はタスクを非表示にします — 自動実行されるものは何もありません |
| `runOptions.instanceLimit`     | 対応     | デフォルトは `1`。上限を超えるとダイアログが開きます（[タスクの実行](#タスクの実行) を参照）                           |
| `runOptions.instancePolicy`    | 制限付き | `prompt` のみサポート。`terminateNewest`、`terminateOldest`、`warn`、`silent` はタスクを非表示にします                 |

### プレゼンテーション

| フィールド                          | 動作 | 備考                                                                                    |
| ----------------------------------- | ---- | --------------------------------------------------------------------------------------- |
| `presentation.echo`                 | 対応 | プロセスの出力の前にコマンドラインをターミナルに書き込みます                            |
| `presentation.reveal`               | 対応 | `always`（デフォルト）、`silent`、または `never` — [タスクの実行](#タスクの実行) を参照 |
| `presentation.focus`                | 対応 | reveal を含意し、キーボードフォーカスをターミナルに移します                             |
| `presentation.panel`                | 対応 | `shared`（デフォルト）、`dedicated`、または `new` — ターミナルの再利用ポリシー          |
| `presentation.clear`                | 対応 | 再利用する再実行の前にターミナルをクリアします                                          |
| `presentation.close`                | 対応 | プロセスの終了時にタブを自動的に閉じます                                                |
| `presentation.preserveTerminalName` | 対応 | プロセスのタイトルの代わりに、タスクのラベルをタブのタイトルとして保持します            |
| `presentation.showReuseMessage`     | 無視 | 純粋に見た目だけの指定です                                                              |
| `presentation.group`                | 無視 | ターミナルのグループ化は対象外です                                                      |

### 無視されるフィールド

これらを含んでいてもタスクは非表示になりません: `problemMatcher`（任意の形式・任意のレベル）、`presentation.revealProblems`、`group`（ビルド / テストのグループ化）、`icon.color`、`presentation.showReuseMessage`、`presentation.group`、`inAgents`。ファイルレベルの `inputs` 配列は単純に読み取られません — ただし、タスク内の `${input:*}` _参照_ はそのタスクを非表示にします（[変数](#変数) を参照）。

## 変数

サポートされる参照です。タスクの解決時に置き換えられます:

| 変数                         | 値                                              |
| ---------------------------- | ----------------------------------------------- |
| `${workspaceFolder}`         | ワークスペースのルートパス                      |
| `${workspaceFolderBasename}` | ワークスペースのルートフォルダ名                |
| `${cwd}`                     | Spirit Desktop 自身のプロセスの作業ディレクトリ |
| `${userHome}`                | OS ユーザーのホームディレクトリ                 |
| `${pathSeparator}`、`${/}`   | OS のパス区切り文字                             |
| `${env:NAME}`                | 環境変数 `NAME`（未設定の場合は空）             |

スキャンの対象は `command`、`args`、`options.cwd`、`options.env` の値、`options.shell` です。その他の `${…}` 参照 — `${file}`、`${selectedText}`、`${lineNumber}`、`${config:*}`、`${command:*}`、`${input:*}`、`${defaultBuildTask}` など — はタスクを非表示にします。ワークスペースが開かれていない場合、`${workspaceFolder}` または `${workspaceFolderBasename}` を参照するタスクは、その解決パスでは非表示になります。

## タスクが非表示になる理由

設定どおりに正確に実行できないタスクは、不完全な設定のまま実行されるのではなく、完全に非表示になります。タスクはパレットから消え、理由は安定したルール id とともに記録されます。

| ルール                       | 理由                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `unsupportedVariable`        | 推測した値で置き換えると、設定とは異なるコマンドが実行されてしまいます                                       |
| `runOn`                      | 自動実行されるものは何もありません — タスクは明示的なクリックからのみ開始されます                            |
| `dependsOnObjectForm`        | 拡張機能型の依存エントリは実行できません                                                                     |
| `dependsOnBackground`        | バックグラウンドタスクは終了しないため、チェーンには明確に待てるものがありません                             |
| `instancePolicy`             | 対話式のプロンプトのみが存在します。サイレントなポリシーは見えないところでインスタンスを終了させてしまいます |
| `cyclicDependency`           | 依存関係の循環は決して開始できません                                                                         |
| `transitiveHiddenDependency` | それ自体が非表示か存在しないラベルに依存しています — 非表示は伝播します                                      |
| `invalidTask`                | ラベルがない（完全に除外される）か、マージチェーンのどこにも `command` がありません                          |

消えたタスクを診断するには、デバッグチャネルを有効にして Desktop を起動します — 非表示になったタスクはすべてルール id とともにログに記録されます:

```bash
SPIRIT_DESKTOP_TASKS_DEBUG=1
```

ログ行の形式は `[desktop-host][tasks] hidden <file>#<label> rule=<id>` です。

## タスクの実行

タスクはパレットでの明示的なクリックからのみ開始されます — フォルダを開いたとき、ファイルを保存したとき、その他のいかなるイベントでも実行されることはありません。これが、`default` 以外の `runOn` の値がサポートされない理由でもあります。

- **依存関係** — `dependsOn` のラベルはマージされた名前空間で解決されます。`dependsOrder: "parallel"`（デフォルト）では、すべての依存関係がそれぞれ独自のターミナルとプレゼンテーションで同時に開始され、メインタスクはすべての依存関係が終了した後にのみ開始されます。いずれかの依存関係が非ゼロで終了した場合、メインタスクは実行されません — VS Code と同じ失敗セマンティクスです。`"sequence"` では、依存関係は順番に 1 つずつ実行され、最初の非ゼロ終了でメインタスクが開始される前にチェーンが中止されます。すでに実行中の依存関係は再起動されず、待機されます。
- **インスタンス上限** — `runOptions.instanceLimit` のデフォルトは `1` です。上限を超えて別のインスタンスを開始すると、実行中のインスタンスとその経過時間が一覧表示されます。1 つを選択（最初のインスタンスが事前選択されます）して **置き換え** を押すとそのインスタンスを終了して新しい実行を開始し、**キャンセル** で中止します。設定された上限を超える選択肢はありません。
- **ターミナルの再利用** — 再利用されるのは終了したタスクのターミナルのみです。`panel: "shared"` と `panel: "dedicated"` はどちらも、このタスク自身のアイドルなターミナルが存在する場合はそれを再利用し（プールはタスクごとです）、存在しない場合は新しいタブを開きます。`panel: "new"` は常に新しいタブを開きます。
- **エコー** — `presentation.echo`（デフォルトでオン）では、コマンドラインがプロセスの出力の前にターミナルに書き込まれます。
- **表示（reveal）** — `always`（デフォルト）は起動時にツールパネルを展開します。`silent` は起動時には閉じたままにし、タスクが非ゼロで終了したときだけ展開します。`never` は自動展開しません。`focus: true` は reveal を含意し、さらにキーボードフォーカスをターミナルに移します。なお、VS Code からの 2 つの相違点があります: `reveal: "silent"` は終了コードが非ゼロの場合にのみ展開します（Spirit には problemMatcher によるトリガーパスがありません）。また `presentation.revealProblems` は一切効果を持ちません — ターミナルの表示を抑制もトリガーもしません。
- **クリア** — `presentation.clear` は、再利用する再実行の前にターミナルをクリアします。
- **クローズ** — `presentation.close` は、終了コードにかかわらず、終了時にタブを自動的に閉じます。
- **ターミナル名の保持** — `presentation.preserveTerminalName` はタスクのラベルをタブのタイトルとして保持します。それ以外の場合は、実行中のプロセスのタイトルに置き換わります。
- **バックグラウンド** — `isBackground: true` はタスクを終了しないものとしてマークします。その終了はユーザーによる終了としてカウントされ、失敗としてはカウントされません（失敗時の reveal なし）。
- **クローズ確認** — `promptOnClose: true` は、プロセスがまだ生きているタブを閉じるときに確認を求めます。確認するとプロセスを終了します。
- **非表示タスク** — `hide: true` のタスクはパレットには表示されませんが、`dependsOn` の依存としては実行できます。

## 例

完全な `.spirit/tasks.json` — build → test → package のシーケンスチェーンに、バックグラウンドの watch タスクを加えたものです:

```json
{
  "schemaVersion": 1,
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "pnpm",
      "args": ["run", "build"],
      "detail": "Production build",
      "icon": { "id": "hammer" }
    },
    {
      "label": "test",
      "command": "pnpm",
      "args": ["run", "test"],
      "dependsOn": ["build"],
      "dependsOrder": "sequence"
    },
    {
      "label": "package",
      "command": "bash",
      "args": ["${workspaceFolder}/scripts/package.sh"],
      "options": {
        "cwd": "${workspaceFolder}",
        "env": { "CHANNEL": "stable" }
      },
      "dependsOn": ["test"],
      "dependsOrder": "sequence",
      "presentation": { "clear": true, "panel": "shared" }
    },
    {
      "label": "watch",
      "command": "pnpm",
      "args": ["run", "watch"],
      "isBackground": true,
      "presentation": { "reveal": "silent", "panel": "dedicated" }
    }
  ]
}
```

- `test` は `build` がゼロで終了した後にのみ実行されます。`package` はその後 `test` の後に実行され、同じターミナルを先にクリアして再利用します。
- `package` は実行時に `${workspaceFolder}` を解決し、`CHANNEL` をプロセス環境に追加します。
- `watch` は邪魔になりません（`silent` は非ゼロ終了時のみ reveal します）。その終了が失敗としてカウントされることはありません。これに依存することはできない点に注意してください — バックグラウンドタスクを指す `dependsOn` エントリは非表示になります。
