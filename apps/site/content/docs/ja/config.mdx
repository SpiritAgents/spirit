共有ユーザーデータの保存先はビルドの quality で決まり、OS のアプリケーションデータディレクトリは使用しません。

## データディレクトリ

`SPIRIT_DATA_DIR` で上書きできます。サーバーは `SPIRIT_SERVER_DATA_DIR` も使用でき（前者よりも優先されます）。

| ビルド | macOS / Linux                             | Windows                                               |
| ------ | ----------------------------------------- | ----------------------------------------------------- |
| Stable | `~/{{product.stable.userDataFolderName}}` | `%USERPROFILE%\{{product.stable.userDataFolderName}}` |
| Dev    | `~/{{product.dev.userDataFolderName}}`    | `%USERPROFILE%\{{product.dev.userDataFolderName}}`    |

Breaking Change：旧プラットフォームディレクトリの読み込みや移行は自動では行いません。データディレクトリの明示的な指定は引き続き使用できます。Electron のキャッシュ、ブラウザーストレージ、ウィンドウ状態はプラットフォーム専用のアプリケーションディレクトリに残ります。

一般的なファイル:

```
{spiritDataDir}/
  config.json
  mcp.json
  hooks.json
  rule.md
  skills/
  chats/
  plans/
  extensions/
  automations/
  dreams/
  server.token
  server/instances/
```

CLI バイナリには SPIRIT_HOME を使用します。Unix では Stable のインストールと共有データが同じ親ディレクトリを使用できますが、bin/ と cli/ はインストールファイルです。インストール設定で共有データディレクトリは変わりません。

## config.json v1

`schemaVersion` は `1` である必要があります。それ以外の値はすべて拒否されます。古いファイルを削除して、[プロバイダーを再接続](./providers.mdx) してください。古い形状からの移行はありません。

主要なフィールド:

- `providers` — 接続済みのプロバイダー：エンドポイント、トランスポート、認証情報、モデル
- `activeModel`
- `imageGenerationModel` / `videoGenerationModel` / `secondaryLanguageModel`
- `agents` — エージェントのトグル（`agents.providerTools.enabled` など）
- `permission` — 許可リストのルール

`activeModel` などのモデルスロットはモデル参照です：`{ "providerId": "…", "name": "…" }`。`providerId` は `providers[].id`、`name` はその `models[].name` のいずれかを指します。

### プロバイダーエントリ

各 `providers[]` エントリは完全な宣言型の接続です。接続ウィザードが書き込んだ内容が、そのままランタイムの読む内容になります。ランタイムがプロバイダーの素性から `apiBase` を再導出することはありません。サイト、プラン、クラウドの選択は接続時に最終 URL へ物化されます。

接続レベルのフィールド:

- `id`（必須）— エントリの一意の ID。モデル参照と内部キーリングのアカウントがこれを指します
- `label` — 任意の表示名
- `apiBase`（必須）— エンドポイント。唯一の真実のソース
- `transportKind` — ワイヤープロトコル：`openai-compatible`（デフォルト）/ `open-responses` / `anthropic` / `bedrock`
- `sdk` — バンドルされた SDK アダプターの完全な npm パッケージ名（例：`@ai-sdk/openai-compatible`）。省略時はトランスポートのデフォルト。未知のパッケージ名は読み込み時に拒否されます
- `headers` — すべての送信リクエストにマージされるリテラルの追加リクエストヘッダー
- `body` — すべてのリクエストボディにマージされるリテラルのフィールド。ワイヤー上の癖を吸収するためのエスケープハッチです。構造化された宣言がある場合はそちらを優先してください
- `providerTools` — プロバイダーが公開するツール（ウェブ検索、コードインタープリター）。[プロバイダーツール](./agent/tools.mdx#provider-tools) を参照してください
- `fileUpload` — インラインに適さないローカルファイルのアップロードチャネル（`path` / `url`、`purpose`、`idPath`、`refTemplate`、`maxBytes`）。省略時はメディアはインラインで送られます
- `imageApi` / `videoApi` — 画像 / 動画生成の API 形状名。省略時はその生成能力なし
- `options` — トランスポートパラメータ。有効なキーは `transportKind` × `sdk` で決まります（bedrock の `awsRegion`、`@ai-sdk/google-vertex` の `project` / `location`、open-responses の `auth` / `storedState` / `applyPatch` スイッチ）。未知のキーは拒否されます
- `models`（必須の配列。空でも可）

モデルレベルのフィールド — `capabilities`、`contextLength`、`outputLimit`、`reasoningEffort`、`supportedReasoningEfforts`、`reasoningMode`、`supportedReasoningModes`、`supportsThinkingType`、`supportsThinkingSwitch`、`thinkingSwitch`、`serviceTiers`、`serviceTier` — はプロバイダーエントリにフラットに宣言でき、すべてのモデルに継承されるデフォルトになります。モデル側の明示的な宣言が優先されます。`models[]` では `name` 以外はすべて任意で、省略は「デフォルト値」ではなく「未宣言」を意味します。

- `capabilities` のトークン：`languageModel`、`image`、`audio`、`video`、`imageGeneration`、`videoGeneration`
- `outputLimit` は出力トークン上限で、`contextLength` とは別です
- `supportedReasoningEfforts` / `supportedReasoningModes` / `serviceTiers` はピッカーと検証の唯一のソースです。リストにない値を選ぶと読み込み時のエラーになり、暗黙に丸められることはありません
- `thinkingEnabled` はあなたの thinking オン/オフの状態です（能力宣言ではありません）。モデルレベルのみで、`supportsThinkingSwitch` の宣言が必要です

### キーチャネル

キーはこのファイルに置く必要はありません。接続ウィザードはデフォルトで [キーリング](./security.mdx) に直接書き込みます。config でチャネルを宣言することもでき、その場合は次の順序で解決されます：

1. `apiKey` — 平文。非推奨。エスケープハッチ専用です
2. `apiKeyEnv` — キーを読み取る環境変数名
3. `apiKeyKeyring` — `{ "service": "…", "account": "…" }`。外部キーリングのエントリ
4. 内部キーリング — ウィザードが書き込む暗黙のフォールバック（アカウント `provider::{id}`）

複合認証情報（Bedrock IAM、Vertex サービスアカウント）は、フラットなキーの代わりに `credentials` スロットマップを使います：

```json
{
  "credentials": {
    "accessKeyId": { "env": "AWS_ACCESS_KEY_ID" },
    "secretAccessKey": { "keyring": { "service": "…", "account": "…" } }
  }
}
```

スロット名はプロトコルのフィールドです — `apiKey`、`accessKeyId` / `secretAccessKey`（Bedrock IAM / SigV4）、`clientEmail` / `privateKey`（Vertex）。未知のスロットは拒否されます。各スロットは `value` → `env` → `keyring` → 内部キーリングの順に解決されます（`provider::{id}::{slot}`。`apiKey` スロットは単なる `provider::{id}`）。フラットなキーと `credentials.apiKey` は同一エントリに共存できません。

### agents.providerTools

`agents.providerTools.enabled` は、プロバイダーが宣言するすべてのツールを一括で制御します（`agents.webSearch.enabled` から改名。セマンティクスは変わりません：オプトアウト式で、デフォルトはオン）。`false` に設定すると、プロバイダーのツールエントリもボディスイッチもリクエストに含まれなくなります。

### カタログの更新と再接続

定期的なカタログ更新は、カタログが所有するモデル宣言フィールド（`capabilities`、`supportedReasoningEfforts`、`supportedReasoningModes`、`serviceTiers` など）を書き換えます。モデルの事実はカタログが唯一の真実のソースなので、これらのフィールドへの手動編集は次回の更新で上書きされます。プロバイダーレベルの物化（`apiBase`、`sdk`、`providerTools`、`fileUpload`、`options`、`imageApi` / `videoApi`）は、プロバイダーを再接続したときだけ変わります。再接続はウィザードが所有するキーをリセットし（それらへの編集は上書きされます）、それ以外はすべて保持します：`label`、認証チャネル、`headers` / `body`、フラットなモデルデフォルト、手動で追加したモデル。

### permission

`permission` は、セッションの [承認レベル](./agent/approvals.mdx) に加えて、個々のシェルコマンドやファイルパスが何をしてよいかを細かく定めます。キーはツール名（`shell`、`read_file`）で、値はワイルドカードパターンから `allow`、`ask`、`deny` へのマッピングです。

```json
{
  "permission": {
    "shell": {
      "git *": "allow",
      "rm -rf *": "deny"
    }
  }
}
```

`deny` は絶対です。承認レベル、フック、セッションメモリのいずれによっても上書きできません。パターン構文、パスの意味、アクションの全リストは [承認](./agent/approvals.mdx) を参照してください。何も実行せずにルールを確認できます: `spirit permission check --shell "git status"`。

古い `tool-permissions.json`（「Always Trust」ボタンが書き込んでいたもの）は非推奨です。コードは読み取りも書き込みも行わず、自動移行もありません。残っているファイルは動作に影響しません。手動で削除してください。

## ワークスペースの `{{product.workspaceDataFolderName}}/`

| パス                                             | 役割                                              |
| ------------------------------------------------ | ------------------------------------------------- |
| `{{product.workspaceDataFolderName}}/rule.md`    | ワークスペースの [ルール](./customize/rules.mdx)  |
| `{{product.workspaceDataFolderName}}/skills/`    | ワークスペースの [スキル](./customize/skills.mdx) |
| `{{product.workspaceDataFolderName}}/mcp.json`   | ワークスペースの [MCP](./customize/mcp.mdx)       |
| `{{product.workspaceDataFolderName}}/hooks.json` | ワークスペースの [フック](./customize/hooks.mdx)  |

また、`{workspace}/AGENTS.md`、`{workspace}/.agents/skills/`、`{workspace}/plans/` も使用されます。
