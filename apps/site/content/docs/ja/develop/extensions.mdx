---

拡張機能は、`.spirit/extension.json`（Spirit マニフェストダンプ）と純粋な npm の `package.json` を持つフォルダーです。Spirit は拡張機能をユーザーごと・ホストごとにインストールし、ワークスペースの `.spirit/` には置きません。各インストールは入手元のマーケットプレイスでスコープされます：インストール ID は `(ソース id, name)` です。

| ホスト  | パス                                                    |
| ------- | ------------------------------------------------------- |
| Desktop | `{spiritDataDir}/extensions/desktop/<sourceId>/<name>/` |
| CLI     | `{spiritDataDir}/extensions/cli/<sourceId>/<name>/`     |

これは [Skills](../customize/skills.mdx)（`SKILL.md` フォルダー）、[MCP](../customize/mcp.mdx)（外部サーバー）、[Hooks](../customize/hooks.mdx)（`hooks.json` スクリプト）とは異なります。`contributes.cli.hooks` は CLI TUI スロットにスタイルを適用するもので、`hooks.json` ではありません。拡張機能は `mcp`、`hooks`、`skills`、`rules` を宣言すれば、同じファイル群を*バンドル*することもできます。

インストール済みの各拡張機能には有効スイッチがあります。無効化またはアンインストールすると貢献は停止します。拡張機能を有効にすることは、宣言された MCP サーバー、エージェントフック、スキル、ルールの実行に同意することを意味します。

ウィザードは拡張機能名（kebab-case）、表示名、一行の説明、スキャフォールドする機能を尋ねます。`package.json`、`icon.svg`、`.spirit/extension.json` を書き込み、選んだ機能に応じたファイル（`skills/<name>/SKILL.md`、`rule.md`、`mcp.json`、`hooks.json`、`styles.css`、`index.mjs`）を追加し、終了時にそのまま貼り付けられるマーケットプレイスエントリを出力します。

スクリプト化する場合、すべての質問にフラグがあります：`[target-dir]`、`--name`、`--display-name`、`--description`、`--capabilities <csv>`、確認をスキップする `--yes`。

結果はいつでも検証できます：

```bash
npx @spiritagent/extension-toolkit check ./my-extension
```

拡張機能ディレクトリに必要なのは `.spirit/extension.json` と `package.json` の 2 ファイルだけ、そして宣言する機能ファイルです：

```text
my-extension/
  .spirit/
    extension.json        # Spirit マニフェストダンプ（必須）
  package.json            # 純粋な npm。読み込まれるのは `main` のみ
  icon.svg                # 任意。SVG のみ、<script> 禁止
  index.mjs               # 任意。`main` が参照する activate エントリ
  mcp.json                # mcp を宣言する場合
  hooks.json              # hooks を宣言する場合（agent hooks）
  rule.md                 # rules を宣言する場合
  skills/<name>/SKILL.md  # skills を宣言する場合
  styles.css              # desktop CSS を宣言する場合（パスはマニフェストから参照）
  cli-hooks.json          # CLI hooks を宣言する場合（パスはマニフェストから参照）
```

`package.json` に Spirit のフィールドはありません——`name`、`version`、`description`、`author`、`homepage`、`license`、`main`、`keywords` は純粋な npm のままです。ホストが読むのは `main` のみ、つまり [`activate`](#activate) のモジュールエントリです。

`.spirit/extension.json` のフィールド：

| フィールド      | 説明                                                                                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | 必須。`1` 固定                                                                                                                                       |
| `name`          | 必須。kebab-case。マーケットプレイス内のエントリ id                                                                                                  |
| `version`       | 必須。semver `major.minor.patch`。プレリリース suffix は未対応                                                                                       |
| `sourceId`      | 必須。所属マーケットプレイスのソース id。ZIP パッケージは任意の値を自己宣言できます（例：`"self-declared"`）。インストールパイプラインが書き換えます |
| `displayName`   | 必須。ユーザーに表示される名前                                                                                                                       |
| `description`   | 必須。一行の概要                                                                                                                                     |
| `icon`          | 任意。拡張機能ルートからの相対 SVG パス                                                                                                              |
| `author`        | 任意。`{ name, email?, url? }` または npm 形式の文字列 `"Name <email> (url)"`                                                                        |
| `category`      | 任意。単一の文字列                                                                                                                                   |
| `keywords`      | 任意。検索キーワードの文字列配列                                                                                                                     |
| `homepage`      | 任意。プロジェクト URL                                                                                                                               |
| `manifest`      | 必須。ランタイム宣言——後述の「`manifest`」節を参照                                                                                                   |

ダンプに `source` やキュレーションフィールド（`reviewStatus`、`featured`）は含まれません——それらはマーケットプレイスエントリのものです。

宣言したファイルは存在し、かつ有効でなければなりません：`mcp`、`hooks`、`skills`、`rules` を宣言しながら対応ファイルがない場合、検証とインストールは失敗します。存在するが宣言されていないファイルは無視され、読み込まれません。

</Tab>
</Tabs>

## `manifest`

`manifest` オブジェクトは拡張機能のランタイム宣言です：どのホストをサポートし、いつアクティブになり、何を貢献するか。マーケットプレイスエントリでは、マニフェストはマーケットプレイス運営者によって裏付けられます。ZIP パッケージでは自己宣言であり、レビュー確認ゲートでゲートされます。

### 機能

| 値                   | ランタイム                                                                       |
| -------------------- | -------------------------------------------------------------------------------- |
| `tool-definitions`   | `contributes.tools` をモデルに公開するには `tool-execution` が必要               |
| `tool-execution`     | これらのツールを実行するには `tool-definitions` が必要                           |
| `system-prompt`      | システムプロンプトフラグメントを提供するには `main` が必要                       |
| `desktop-ui`         | `contributes.desktop` と対で指定する必要があります                               |
| `cli-ui`             | `contributes.cli` と対で指定する必要があります                                   |
| `mcp`                | `contributes.mcp` と対で指定し、パッケージルートの `mcp.json` を読み込みます     |
| `hooks`              | `contributes.hooks` と対で指定し、パッケージルートの `hooks.json` を読み込みます |
| `skills`             | `contributes.skills` と対で指定し、`skills/<name>/SKILL.md` を読み込みます       |
| `rules`              | `contributes.rules` と対で指定し、パッケージルートの `rule.md` を読み込みます    |
| `approval-flow`      | 宣言のみ。承認は各ツールの `approvalMode` によって行われます                     |
| `questions-flow`     | 宣言のみ。質問は `approvalMode: need-questions` によって行われます               |
| `settings`           | 宣言のみ。設定は `settingsSchema` から取得されます                               |
| `secret-storage`     | `secretSlots` と一緒に使用されます                                               |
| `structured-results` | 宣言のみ                                                                         |

`desktop-ui` / `cli-ui` / `mcp` / `hooks` / `skills` / `rules` と対応する `contributes` は、両方存在するか、両方存在しないかのどちらかでなければなりません。

### アクティベーションイベント

| イベント               | 発火タイミング                     |
| ---------------------- | ---------------------------------- |
| `onStartup`            | ホストのウォームアップ             |
| `onExtensionInstalled` | インストール完了後                 |
| `onSessionOpened`      | セッションがアクティブになったとき |
| `onSessionReset`       | セッションのリセット               |
| `onUserMessage`        | ユーザーがメッセージを送信したとき |
| `onToolCall`           | ツールが実行されようとしているとき |
| `onToolResult`         | ツールの結果が利用可能になったとき |
| `onApprovalResolved`   | 承認の決定が解決されたとき         |

ホストは、拡張機能がイベントをリストし、読み取り可能な `main` を持っている場合に `activate` を呼び出します。

### `contributes.tools`

| フィールド      | 説明                                                      |
| --------------- | --------------------------------------------------------- |
| `name`          | 必須。`[a-z0-9]+(?:[._-][a-z0-9]+)*`                      |
| `description`   | 必須。モデルに表示されます                                |
| `inputSchema`   | 必須。JSONスキーマオブジェクト                            |
| `outputSchema`  | 任意。JSONスキーマオブジェクト                            |
| `approvalMode`  | 任意。`allowed`、`need-approval`、または `need-questions` |
| `executionMode` | 任意。`foreground` または `background`                    |

モデルは `name` をそのまま認識しません。ホストは `extension__{id}__{tool}__{hash}` のような呼び出し名を構築します。

### `contributes.desktop`

`desktop-ui` が必要です。

| フィールド     | 説明                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| `css[].path`   | 必須。パッケージルートからの相対パスで指定するCSSファイル                  |
| `css[].media`  | 任意。CSSメディアクエリ                                                    |
| `settingsPage` | 任意。`true`、`{}`、または `{ title }` — Desktopの設定エントリを追加します |

### `contributes.cli`

`cli-ui` が必要です。`hooks` はインライン配列ではなく、`path` を持つオブジェクトです:

```json
{
  "hooks": { "path": "cli-hooks.json" }
}
```

ファイルは `{ "hooks": [ ... ] }` の形式である必要があります。

| フィールド | 説明                                                                 |
| ---------- | -------------------------------------------------------------------- |
| `slot`     | 必須。以下のスロットのいずれか                                       |
| `variant`  | 任意。`default`, `accented`, `muted`, `warning`, `success`, `danger` |
| `tokens`   | 任意。`{ foreground?, border?, accent? }`                            |
| `prefix`   | 任意。文字列                                                         |
| `suffix`   | 任意。文字列                                                         |

スロット: `message.user`, `message.assistant`, `message.tool`, `assistant.thinking`, `input.frame`, `bottom_form`, `bottom_form.section`, `slash_suggestions`, `approval.panel`, `questions.panel`。

トークンの役割: `default`, `primary`, `secondary`, `muted`, `accent`, `success`, `warning`, `danger`。

```json
{
  "hooks": [
    {
      "slot": "input.frame",
      "variant": "accented",
      "tokens": { "border": "accent" },
      "prefix": "[",
      "suffix": "]"
    }
  ]
}
```

### バンドルする MCP、hooks、skills、rules

対応する capability が必要です。`contributes.mcp`、`contributes.hooks`、`contributes.skills`、`contributes.rules` は `true` または `{}` です。パスは規約どおりで、カスタム path はできません。

| 貢献        | Capability | ファイル                                                                                             |
| ----------- | ---------- | ---------------------------------------------------------------------------------------------------- |
| MCP         | `mcp`      | パッケージルートの `mcp.json`（ユーザー/ワークスペース MCP と同じ schema）                           |
| Agent hooks | `hooks`    | パッケージルートの `hooks.json`（agent hooks と同じ schema。`contributes.cli.hooks` ではありません） |
| Skills      | `skills`   | `skills/<name>/SKILL.md`                                                                             |
| Rules       | `rules`    | パッケージルートの `rule.md`                                                                         |

宣言したのにファイルが無い、または不正な場合はインストールに失敗します。宣言されていないファイルは無視され、読み込まれません。

相対 `command` / `cwd` は拡張機能ルート基準です。MCP stdio で `cwd` を省略すると拡張機能ルートになります。

拡張機能が有効なときだけセッションに overlay され、**設定 → MCPs | Hooks | Skills | Rules** には出ません。名前の衝突は workspace > user > extension です。

### `settingsSchema`

| フィールド     | 説明                                                       |
| -------------- | ---------------------------------------------------------- |
| `key`          | 必須。ツール名と同じパターン                               |
| `type`         | 必須。`string`, `boolean`, `number`, または `select`       |
| `title`        | 必須。UIラベル                                             |
| `description`  | 任意                                                       |
| `placeholder`  | 任意                                                       |
| `required`     | 任意。ブール値                                             |
| `defaultValue` | 任意。`type` と一致する必要があります                      |
| `options`      | `select` には必須。`{ value, label, description? }` の配列 |

値は `string`, `number`, `boolean`, または `null` です。`null` は必須でない設定をクリアします。

### `secretSlots`

| フィールド    | 説明           |
| ------------- | -------------- |
| `key`         | 必須           |
| `title`       | 必須           |
| `description` | 任意           |
| `required`    | 任意。ブール値 |

デスクトップはシークレットをOSキーリングに保存します。CLIデーモンパスでは、`secrets.set` / `secrets.delete` が利用できない場合があります。

## `activate`

`main` は動的な `import` で読み込まれます。次のいずれかをエクスポートします:

- `export function activate(ctx) { ... }`
- `export default function activate(ctx) { ... }`
- `export default { activate }`

### `ctx`

| フィールド        | 説明                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `extension`       | `{ id, name, version, directoryPath, manifestPath, main }`                                                     |
| `host`            | ホストAPI。デスクトップは `showMessageBox` を実装します。CLIは `{}`                                            |
| `log`             | `(message: string) => void`                                                                                    |
| `settings`        | `get(key)`, `getAll()`, `set(key, value)`, `setAll(values)`                                                    |
| `secrets`         | `get(key)`, `has(key)`, `set(key, value)`, `delete(key)` — キーは `secretSlots` で宣言されている必要があります |
| `activationEvent` | 任意。`{ type, detail? }`                                                                                      |

### 戻り値

オブジェクトを返すか、モジュールから同じフィールドをエクスポートします。

| フィールド        | 説明                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------- |
| `tools`           | `Record<string, (ctx) => unknown>`。キーはマニフェストのツール名です                    |
| `invokeTool`      | `(ctx) => unknown`。存在する場合は `tools[name]` の代わりに使用されます                 |
| `systemPrompt`    | 静的システムフラグメント                                                                |
| `getSystemPrompt` | `() => string \| Promise<string>`。存在する場合は `systemPrompt` の代わりに使用されます |
| `onEvent`         | `(event) => void`                                                                       |
| `dispose`         | `() => void`。削除または再読み込み時に呼び出されます                                    |

### ツールハンドラー `ctx`

| フィールド        | 説明                                                          |
| ----------------- | ------------------------------------------------------------- |
| `extension`       | `activate` と同じランタイム情報                               |
| `host`            | 同じホスト API                                                |
| `toolName`        | マニフェストのツール名                                        |
| `arguments`       | モデルからのオブジェクト                                      |
| `log`             | 同じロガー                                                    |
| `settings`        | 同じ設定アクセサー                                            |
| `secrets`         | 同じシークレットアクセサー                                    |
| `toolCallId`      | 任意                                                          |
| `questionsResult` | 任意。`approvalMode` が `need-questions` の場合に設定されます |

`string` の結果はそのまま渡されます。その他の値は `JSON.stringify(value, null, 2)` になります。`undefined` は `""` になります。

### デスクトップ `host.showMessageBox`

| フィールド  | 説明                                                 |
| ----------- | ---------------------------------------------------- |
| `title`     | 必須。文字列                                         |
| `message`   | 必須。文字列                                         |
| `detail`    | 任意。文字列                                         |
| `buttons`   | 任意。文字列配列                                     |
| `cancelId`  | 任意。数値                                           |
| `defaultId` | 任意。数値                                           |
| `noLink`    | 任意。ブール値                                       |
| `type`      | 任意。`none`、`info`、`error`、`question`、`warning` |

```js
export function activate(ctx) {
  return {
    systemPrompt: "Use lookup_item when the user asks for an item by id.",
    async invokeTool({ toolName, arguments: args, settings, secrets }) {
      if (toolName !== "lookup_item") {
        throw new Error(`Unknown tool: ${toolName}`);
      }
      const region = await settings.get("region");
      const token = await secrets.get("api_token");
      return { id: args.id, region, hasToken: Boolean(token) };
    },
    dispose() {
      ctx.log("example-extension disposed");
    },
  };
}
```

## ZIP として配布する

拡張機能ディレクトリを共有可能な ZIP 形式（コンテンツと `.spirit/extension.json`）にパックします：

```bash
npx @spiritagent/extension-toolkit pack ./my-extension
```

このコマンドはまずパッケージを検証し、`<name>-<version>.zip` をカレントディレクトリに書き込みます。ユーザーは**拡張機能**ページまたは `spirit extension import` で ZIP をインポートします。それは個人マーケットプレイスに登録されます。[拡張機能](../customize/extensions.mdx)を参照してください。

拡張機能をマーケットプレイスに登録する場合は、[publish で公開する](#publish-で公開する)を参照してください。

## リモート拡張機能マーケットプレイスを運営する

リモート拡張機能マーケットプレイスとは、`.spirit/marketplace.json` インデックスを提供するサービス可能なディレクトリです：Git リポジトリ、静的サイト、またはローカルディレクトリ。ユーザーは `spirit extension marketplace add <url|path>` または Desktop の**拡張機能**ページで追加し、エントリを閲覧・インストールします。

<Tabs items={["テンプレートリポジトリ", "手動で作成"]}>
<Tab value="テンプレートリポジトリ">

[Use this template](https://github.com/new?template_owner=SpiritAgents&template_name=extension-template) から `SpiritAgents/extension-template` を使って独自のマーケットプレイスリポジトリを作成できます。

テンプレートにはレジストリレイアウト、2 つのサンプル拡張機能、そして push と pull request のたびにレジストリを検証する CI が含まれています。拡張機能を公開するには：

1. `npm create @spiritagent/extension` でスキャフォールドする。
2. `npx @spiritagent/extension-toolkit publish ./my-extension /path/to/your-marketplace-clone` を実行する——拡張機能が `extensions/` にコピーされ、エントリが `.spirit/marketplace.json` にマージされます。[publish で公開する](#publish-で公開する)を参照してください。
3. プッシュする——ユーザーはその Git URL でマーケットプレイスを追加します。

</Tab>
<Tab value="手動で作成">

マーケットプレイスのルートは、インデックスと拡張機能ごとのコンテンツディレクトリを保持します：

```text
my-marketplace/
  .spirit/
    marketplace.json  # インデックス
  extensions/
    my-extension/     # コンテンツディレクトリ（純粋な npm パッケージ + 機能ファイル）
      icon.svg
      package.json
      ...
```

`marketplace.json` 内の相対パスはマーケットプレイスルートを基準に解決され、`..` セグメントや絶対パスは許可されません。

エントリのフィールドを意味グループ別に：

- **ID**——`name`（kebab-case。エントリ id）、`version`（semver。プレリリースなし）、`source`：ローカルコンテンツの場合はルート相対パス文字列（例：`"./extensions/my-extension"`）、または `{ "source": "npm", "package": "@scope/name@1.0.0" }` で正確な npm バージョンを固定（インストール時に packument の SRI ハッシュで整合性が検証されます）。
- **表示**——`displayName`、`description`、`icon`（ルート相対 SVG パス）、`category`、`keywords`、`homepage`、`author`。
- **宣言**——`manifest`：前述の「`manifest`」節で説明したランタイム宣言。マーケットプレイスがこれを裏付けます。パッケージが単独で機能を主張することはできません。
- **キュレーション**——`featured` と `reviewStatus`（`unverified` / `verified` / `revoked`）。

`extension-toolkit publish` でエントリのマージを自動化できます——[publish で公開する](#publish-で公開する)を参照してください。

レジストリをローカルで検証——オフライン：schema、kebab-case 名、プレリリースなしの semver、npm source 形式、ローカル source の宣言-コンテンツファイル、アイコンルール：

```bash
npx -y @spiritagent/extension-toolkit marketplace check .
```

レビュー規律：エントリを追加する、または `version` を変更する PR は `reviewStatus: "unverified"` を維持しなければなりません。人間のレビュー後に別コミットで `verified` に昇格させます。テンプレートリポジトリの `.github/workflows/marketplace.yml` が参照実装です——PR ベースに対してインデックスを diff します。

</Tab>

### ローカルマーケットプレイス

`.spirit/marketplace.json` を持つ任意のローカルディレクトリはマーケットプレイスとして追加できます——`spirit extension marketplace add <path>` または Desktop の**ディスクから追加**で。ローカルマーケットプレイスはその場で読み取られ、CI は不要です。拡張機能作者の開発ループとしても使えます：編集、再インストール、繰り返し。

### publish で公開する

`extension-toolkit publish` は拡張機能の `.spirit/extension.json` を対象マーケットプレイスの `.spirit/marketplace.json` にマージし、エントリの source が必要とするコンテンツをコピーします：

```bash
npx @spiritagent/extension-toolkit publish ./my-extension ./my-marketplace
```

- 第 1 引数は拡張機能ディレクトリ、第 2 引数はマーケットプレイスのルート——`.spirit/marketplace.json` を持つ任意のローカルディレクトリ：テンプレートリポジトリのクローン、`{spiritDataDir}/marketplaces/personal` の個人マーケットプレイスなど。
- `--source local`（デフォルト）：パッケージ全体をマーケットプレイスの `extensions/<name>/` にコピーし（`.spirit/extension.json` を含み、`node_modules` と `.git` は除外）、エントリの `source` をそこに向けます。
- `--source npm`：拡張機能の `package.json` から `name@version` を読み取り、エントリの npm `source` として固定します。宣言されたアイコンのみを `extensions/<name>/` にコピーします（アイコンはマーケットプレイスが自己ホスト）。npm パッケージ自体の公開は、引き続き npm CLI で行います。
- `--dry-run`：書き込まれるエントリと予定されるアクションを表示し、ディスクには書き込みません。
- マージ規則：同名エントリはその位置で置き換え、なければ追加します。新規エントリや `version` 変更時は `reviewStatus` が `unverified` に戻り、同バージョンの再公開では維持されます。`featured` などのキュレーションフィールドは常にマーケットプレイス側の値を保持します。
- 公開前に `check` と同じ検証が実行されます。失敗時は何も書き込まれません。
